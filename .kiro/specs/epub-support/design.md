# EPUB design

## Container and package

The in-repo reader uses the existing shared ZIP preflight and locked rust libraries for ZIP and XML. The preflight bounds central directory work and checks local/central consistency before indexing. The EPUB layer compares the archive readers' entry views, opens the single declared package, then bounds each resource read and the cumulative read budget. Paths use `/` and resolve only inside the publication. Runtime operations are in-process and offline.

`epub.rs` owns the OPF metadata, manifest and spine, EPUB 3 navigation and EPUB 2 NCX, and guarded resource I/O. `epub_content.rs` maps namespace-aware XHTML onto ordered document blocks. Tables carry semantic cells with nested blocks, spans, headings and row-group metadata. Images retain source bytes, alternative text and inline position. SVG uses a restricted static profile. MathML extraction retains a namespace-complete source fragment and readable text from the primary presentation branch. `epub_overlay.rs` reads each referenced SMIL timing tree once, resolves local text and audio paths, and validates target IDs when their XML members are parsed.

## Public API and output

The existing native extraction, render, and conversion operations dispatch to EPUB. Python also exposes bounded resource ranges and ordered per-chapter media cues. Cue audio points to packaged bytes and uses integer microseconds for clip timing. The timing tree preserves sequence scope and semantic roles. The Python binding uses `epub_audio.rs` to decode one cue at a time, keeping a decoder for the current track. WAVE reads seek directly to the selected PCM samples. MP3 and AAC keep codec state and the last decoded frame for adjacent cues. MP3 restarts for backward seeks and AAC warms up the preceding access units when seeking. `epub_aac.rs` bounds MP4 boxes and sample-table expansion before demux, validates the resulting local access unit ranges, and applies a continuous edit list to the presentation time. Playback yields each target's audio or text and uses blocking sinks with active-target callbacks to synchronize highlighting.

`epub_editor.rs` handles targeted OPF metadata updates and batch XHTML replacements. It stages changes, resolves repeated spine positions to their shared file, checks existing text anchors, and rebuilds the ZIP through the bounded sink. The chapter editor validates the complete tentative book before returning its bytes. Untouched members keep their uncompressed content, with archive header details subject to the writer.

`epub_media.rs` collects XHTML audio and video references in the page metadata under the existing semantic output budget. It resolves local sources, posters, and caption tracks against the package manifest and archive. The inventory retains remote URLs without opening them. An element's src attribute takes precedence over child source options. The shared audio codec resolver checks package media types and source codec hints. The Python API chooses a local source and streams through the same native decoder and chunk reader used for SMIL. The XHTML preview uses the existing image path for packaged posters and otherwise displays authored fallback content. The chapter editor checks retained media references with its XML dependency scan and supports WebVTT and TTML resources. WebM and Ogg video decoding and timed-text rendering remain open. [HTML media elements](https://html.spec.whatwg.org/multipage/media.html)

`epub_video.rs` reuses the bounded MP4 scan in `epub_mp4.rs` and indexes local sample ranges with the locked MP4 demuxer. It checks AVC parameter sets before allowing the in-process decoder to allocate pictures. Coded frames are bounded to an area of 1920 × 1088 pixels, and reference and reorder buffers are bounded to 16 pictures. Each call may feed up to 512 access units while seeking and waiting for a frame. The adapter drives the decoder in sample decode order, checks each frame against the sorted composition timestamps, and applies a continuous MP4 edit and the requested clip to the output intervals. It converts its 8-bit YUV 4:2:0 planes to packed RGB8 using the declared matrix and range, and carries the pixel aspect ratio separately. The iterator emits one owned frame at a time. The existing AAC-LC adapter opens the same packaged MP4 source for audio. Both endpoints take presentation microseconds so the caller can schedule them on one clock. [OxideAV H.264 decoder](https://github.com/OxideAV/oxideav-h264)

`epub_structure.rs` stages a replacement spine and manifest additions. It retains original itemrefs, assigns unique paths and IDs to new chapters, and shares the editor’s ZIP writer. `epub_toc_edit.rs` updates EPUB 3 navigation and EPUB 2 NCX in the same transaction. Navigation groups keep their hierarchy and use each group’s earliest surviving spine target for sibling ordering. Omitted chapters stay in the manifest and archive so references from other chapters or media overlays can still resolve. New SVG spine chapters are fixed-layout and use the standalone SVG media type. A staged archive read resolves their stylesheets and raster resources through the SVG renderer before return. New and replaced local assets are bounded, and the completed archive is parsed again before return. Chapter replacement preserves the existing media type and reuses anchor validation for XHTML and SVG. Fixed chapters keep a numeric viewport or viewBox.

`epub_output.rs` projects supported semantic blocks into the existing WordCraft model. The WordCraft web layout handles unstyled reflowable previews. The native DOCX and PDF exporters handle document pagination in the semantic profile. The bounded `epub_math.rs` adapter substitutes an equation object at each formula's original text span and lets the pinned math engine shape it.

## Creation and dependency scope

`EditableEpub` validates and escapes semantic EPUB 3 source, then calls rbook 0.7.12 with only its write feature. Writes run through a bounded sink. The public creation APIs do not accept externally supplied XHTML, OPF, or archive entry names. Authoring and metadata editing use the same output limit. Input, output, XML and resource limits bound the work of individual stages. They do not measure total process memory.

This design replaces LexePub and retains the existing rbook writer. It requires no craft-libs EPUB proposal or change to the shared backend revision. The read and creation paths are independently exercised by round-trip tests.

Container limits, repeated metadata, namespace preservation, links, table spans, and image handling are owned by the local reader. The existing writer accepts a bounded sink and publication dates at its current pin.

## Source rendition

Source rendering reads the original target resource to retain CSS selector context and author geometry. `epub_css.rs` loads and parses local styles with Raffia and resolves the supported selectors under a work budget. It indexes rules by a required ID, class, or tag in the subject compound. Candidate rules still use the full selector matcher, and cascade priorities retain original rule order. `epub_style.rs` maps the cascade and inherited typography onto Taffy and native WordCraft properties. `epub_layout.rs` shapes text and math, measures and lays out boxes, then paints the composed draw list through the native renderer. SVG content documents and embedded images use the validated static profile and resvg. Embedded SVG is rasterized with transparency in its layout box. Semantic DOCX and PDF export use PNG for the static SVG image. Styled reflowable chapters use the existing 80,000-point paint coordinate limit. The renderer checks the requested raster region against the shared DPI and pixel limits before building the draw list.

The EPUB adapter owns author stylesheet resolution and knows only archive paths. It never delegates fetching to a renderer. Raffia, Taffy and resvg are locked crates with permissive licensing. `epub_fonts.rs` registers bounded local fonts in a chapter-owned Parley collection. It uses WordCraft's existing web-font decoding and bundled fallbacks, without adding faces to its process-wide font database. For ranged XHTML faces, the adapter intersects the font's character map with the CSS ranges in a bounded in-memory copy. It uses the existing locked `write-fonts` package to write the effective map, including covered variation sequences, and preserves the original packaged bytes. Parley tries equal-style faces in reverse declaration order. The adapter preserves the ordered named and generic families on each styled text run and registers author faces under private family names to keep scoped glyph coverage separate from bundled names. Parley tries the specified XHTML families before the bundled fallback. Mixed text remains shaped around image and native equation boxes. Tables using packaged fonts derive cell placements and spans from the validated semantic table grid. `epub_obfuscation.rs` recognizes the IDPF font-only declaration and applies it to preview reads after verifying the targets against the package manifest. Resource reads return the stored bytes.

`epub_svg.rs` applies the shared EPUB cascade to SVG prolog stylesheets and embedded declarations in source order. It sends only supported presentation properties and same-document paint references to resvg. SVG images carry their archive resolution base independently of the original markup and public image name. The renderer supplies PNG or JPEG resources through a bounded in-memory resolver. The SVG font database is scoped to the rendition and registers packaged fonts under their CSS family names. External resolvers for file and data URLs are disabled. `epub_svg_use.rs` checks each use target against an ID in the same SVG subtree and measures the expanded tree before usvg creates instances. It rejects duplicate targets and cycles, and bounds expanded nodes, referenced-subtree visits, payload bytes and depth. The renderer repeats the measurement after applying CSS so computed style bytes are counted in each instance. usvg handles instance geometry, viewport sizing and presentation inheritance. [SVG use elements](https://www.w3.org/TR/SVG2/struct.html#UseElement)

`epub_svg_effects.rs` validates same-document linear and radial gradient templates against unique IDs and limits each template chain to 32 references. usvg resolves inherited gradient stops and geometry. A filter may contain one Gaussian blur primitive with SourceGraphic or SourceAlpha input. The adapter checks filter references from XML and computed CSS. After usvg expands instances, the adapter measures each filtered layer at the requested scale. It bounds each layer to 8 Mi pixels, total filter work to 32 Mi pixels per SVG raster, and the standard deviation to 1,024 pixels per axis. Blur inside a pattern, mask or clip path is unsupported. [SVG gradient templates](https://www.w3.org/TR/SVG2/pservers.html#LinearGradientElement), [Gaussian blur](https://www.w3.org/TR/filter-effects-1/#feGaussianBlurElement)

XHTML parses literal CSS `font-variation-settings` with Raffia, inherits or clears the axis list through the cascade and supplies the resulting coordinates to Parley. Automatic optical sizing sets `opsz` from the font size in points when the author has not supplied that axis. The renderer draws glyph outlines at the normalized coordinates returned by shaping. SVG previews pass the corresponding stylesheet properties through to resvg.

The XHTML and SVG cascades compute unregistered custom properties on each element before substituting var() in supported declarations. Case-sensitive names, the inherited computed values, dependencies inside fallbacks, and shorthand cascade order are preserved. Each declaration, dependency depth and chapter-wide substitution work is bounded. SVG still checks resolved paint values before passing them to resvg. [CSS custom properties](https://www.w3.org/TR/css-variables-1/)

Broader selectors, registered CSS custom properties, SVG font Unicode ranges and fallback stacks, variable `@font-face` descriptor ranges and defaults, additional SVG features and semantic fixed-layout conversion remain open.


## Presentation MathML

`epub_math.rs` projects bounded Presentation MathML to the pinned WordCraft equation model for layout and export. The equation envelope carries root size and foreground, and OMML runs carry inherited size, foreground and variant. Presentation and syntax nodes share a projection budget. Each tensor pair contributes one native script level to the depth guard, including levels generated for prescripts. Variable fences and separators use explicit math runs when the native delimiter cannot hold the full sequence.

Extraction and native equation projection share a token whitespace normalizer. It drops container indentation from extracted text and collapses XML whitespace inside tokens. Nonbreaking spaces remain literal. The MathML source remains available with its indentation and annotations. The large-sample check uses the existing semantic output limits. [MathML whitespace rules](https://www.w3.org/TR/MathML3/chapter2.html#fund.collapse)

The EPUB stylesheet cascade resolves declarations on the source chapter before detaching an equation. Equation descendants use a sparse style map with a 64 MiB accounting limit, separate from the 8,000-box style limit. Annotation subtrees are inert. The preview and export paths attach a bounded snapshot of the supported declarations and the enclosing font size and foreground. The equation projector applies those declarations over same-element presentation hints and evaluates relative sizes in the equation's inherited context. Fixed-layout previews use the chapter viewport. The semantic export path applies these styles within equations. Public extraction retains the original MathML markup.

WordCraft represents zeroed `mpadded` metrics with its visible phantom node. Horizontal `mspace` uses a sized math-space run and follows native script scaling. The emitted OMML retains that run. Custom rule thickness, arbitrary vertical spaces and padding shifts, and structures beyond the documented profile remain open.

`epub_math_table.rs` projects spanning tables onto bounded grids of up to 128 rows and 32 columns each. The span map rejects overlapping cells and row spans past the last row. The projector recognizes a nested spanning table when it is the sole expression in its containing cell. It shares the formula depth and node budgets across all grids. The node budget includes implicit grid entries materialized by native export. The grid uses the pinned equation shaper for ordinary cells and the nested grid's width, height and baseline for table cells. The renderer draws each grid inside its containing inline box. A standalone table that fits the available export page becomes a native merged table with editable equations and native nested tables in its cells. PDF retains searchable cell text. Spanning tables within arbitrary expressions and semantic export mixed with other paragraph content return explicit unsupported errors. [MathML table cell spans](https://www.w3.org/TR/mathml-core/#entry-in-table-or-matrix-mtd)


## Resource removal and media overlay authoring

Chapter edits derive the EPUB 3 `mathml` and `svg` declarations from element namespaces in the new XHTML. Replacement splices only the affected manifest attributes into the original OPF. Insertion uses the same scanner when adding new manifest entries. EPUB 2 retains its existing package vocabulary.

The structure editor rewrites the spine and navigation first, then stages narration association and duration edits. It creates one SMIL document per edited chapter with ordered sequences and text and audio cues. The Python facade sends a bounded depth-first list, and the native writer validates its parent-child transitions and emits `seq` and `par` elements. Sequences point to the chapter or a fragment, and their roles apply to descendant cues during playback. Durations use checked microsecond arithmetic. The package total sums each associated overlay once. Retained overlays use declared duration metadata or explicit clip ranges when available. When an edited chapter leaves a shared SMIL resource, the editor removes timed cues for that chapter and prunes empty sequences. A container targeting a removed chapter is retargeted to its first surviving cue's content document. The retained cues keep their order, IDs, fragments, audio sources, and roles. Open-ended clips use bounded local audio presentation durations in the Python build, including staged resource replacements. If the audio duration is unavailable, an unchanged SMIL declaration can supply the retained duration when every removed clip has known timing and the retained open sources are unchanged. Text-only cues contribute zero recorded duration.

Resource removal checks the staged archive after additions, replacements, and overlay changes. It validates retained package ID references, targets in XHTML, SVG, SMIL and NCX, and stylesheet dependencies. The scan follows archive-local stylesheet links and imports regardless of media conditions. It includes recognized off-spine resources and excludes the removed members, allowing jointly removed assets to reference each other. Unprovable scripted dependencies fail explicitly. Untouched ZIP members are raw-copied. The reader reopens and validates the entire result before returning bytes.

An IDPF-obfuscated font replacement validates the plain input within the shared font budget and applies the original package's obfuscation key before writing the member. After a successful staged reference check, removing a font splices its declaration out of the encryption document. Removing the last declared font removes the encryption document from the archive as well.


## Media overlay playback

`epub_audio.rs` maps SMIL time bounds to half-open sample-frame intervals. Streaming advances that integer cursor using PCM frames returned by the decoder. It reuses the track and its decoded frame cache between reads and supports an open-ended interval through the end of the resource. The MPEG decoder verifies a supported Xing/Info tag against packet headers before applying its encoder delay, decoder delay and end padding. AAC uses the MP4 presentation edit.

`epub_ogg.rs` validates each Ogg segment's BOS and EOS boundaries, serial numbers, page sequence, lacing, and packet budgets. It passes the selected Opus stream's pages to the checksum-verified packet reader and verifies checksums on every other stream without assembling its packets. Selection uses the requested zero-based Opus ordinal in identification page order within each segment. Without a request, each segment must contain a single Opus stream. The Python narration entry points accept a mapping from decoded resource paths to ordinals. SMIL continues to reference the resource and its authored time interval. Overlay reading and editing accept `audio/ogg`, `application/ogg` and `video/ogg` containers that carry the supported audio. `epub_opus.rs` indexes packet times at 48 kHz from their Opus frame headers, verifies that all coded substreams in a packet have the same duration, and validates page granule positions against those times. The decoder applies each logical stream's identification gain, pre-skip and final granule. It joins consecutive Opus streams on a single presentation timeline and retains one active link decoder for bounded clip reads and seeks. It reorders family-1 samples from Vorbis speaker order to the order specified by the WAVE speaker mask. A chain keeps a single WAVE layout using the combined speaker positions of its non-mono links. Mono uses the center position when available and otherwise plays through the left and right front speakers. Absent channels are silent. The file-wide page and packet limits include every link. Index and clip limits count each coded substream packet.

The Python iterator seeks by chapter cue index before applying role filters. It decodes each selected target as a group of chunks. Playback calls the target callback once before handing that group's audio or text to the sinks and clears the target when the group finishes or a sink fails.


## Fixed-layout spreads and visual export

The reader preserves package progression and spread settings and spine-level placement and spread overrides. EPUB spread preview pairs fixed-layout entries in progression order. Centered entries, reflowable chapters and entries where the active spread policy disables facing pages use an individual viewport. Non-linear entries can be previewed individually. The first automatic placement is the trailing slot. A missing companion is a white slot with the dimensions of the present chapter.

XHTML and SVG render into the shared pixel-region format. Spread composition places their original-sized rasters edge to edge, aligns their top edges, and paints only regions that intersect the requested clip. Fixed-layout visual PDF export renders each requested chapter as a full-page image and passes its original viewport to the pinned PDF writer. The export bounds aggregate pixel and encoded-image counts.
