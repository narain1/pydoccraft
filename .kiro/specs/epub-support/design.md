# EPUB design

## Container and package

The in-repo reader uses the existing shared ZIP preflight and locked rust libraries for ZIP and XML. The preflight bounds central directory work and checks local/central consistency before indexing. The EPUB layer compares the archive readers' entry views, opens the single declared package, then bounds each resource read and the cumulative read budget. Paths use `/` and resolve only inside the publication. Runtime operations are in-process and offline.

`epub.rs` owns the OPF metadata, manifest and spine, EPUB 3 navigation and EPUB 2 NCX, and guarded resource I/O. `epub_content.rs` maps namespace-aware XHTML onto ordered document blocks. Tables carry semantic cells with nested blocks, spans, headings and row-group metadata. Images retain source bytes, alternative text and inline position. SVG uses a restricted static profile. MathML extraction retains a namespace-complete source fragment and readable text from the primary presentation branch. `epub_overlay.rs` reads each referenced SMIL timing tree once, resolves local text and audio paths, and validates target IDs when their XML members are parsed.

## Public API and output

The existing native extraction, render, and conversion operations dispatch to EPUB. Python also exposes bounded resource ranges and ordered per-chapter media cues. Cue audio points to packaged bytes and uses integer microseconds for clip timing. The timing tree preserves sequence scope and semantic roles. The Python binding uses `epub_audio.rs` to decode one cue at a time, keeping a decoder for the current track. WAVE reads seek directly to the selected PCM samples. MP3 and AAC keep codec state and the last decoded frame for adjacent cues. MP3 restarts for backward seeks and AAC warms up the preceding access units when seeking. `epub_aac.rs` bounds MP4 boxes and sample-table expansion before demux, validates the resulting local access unit ranges, and applies a continuous edit list to the presentation time. Playback yields each target's audio or text and uses blocking sinks with active-target callbacks to synchronize highlighting.

`epub_editor.rs` handles targeted OPF metadata updates and batch XHTML and SVG replacements. It stages changes and resolves repeated spine positions to their shared file. When a replacement removes an element ID, the editor checks hyperlinks in the staged replacements and retained content documents, including non-spine resources, navigation, the package guide and compatibility NCX. It checks retained overlay targets from the parsed timing trees. Links to previously missing IDs stay as authored. The editor rebuilds the ZIP through the bounded sink. The chapter editor validates the complete tentative book before returning its bytes. Untouched members keep their uncompressed content, with archive header details subject to the writer.

`epub_media.rs` collects XHTML audio and video references in the page metadata under the existing semantic output budget. It resolves local sources, posters, and caption tracks against the package manifest and archive. The inventory retains remote URLs without opening them. An element's src attribute takes precedence over child source options. Codec hints and package media types identify playback candidates. The Python API tries local candidates in authored order and advances to the next on an unsupported codec or profile. Audio streams through the native decoder and chunk reader used for SMIL. The XHTML preview uses the existing image path for packaged posters and otherwise displays authored fallback content. The chapter editor checks retained media references with its XML dependency scan and supports WebVTT and TTML resources. Styled timed-text rendering remains open. [HTML media elements](https://html.spec.whatwg.org/multipage/media.html)

`epub_video.rs` reuses the bounded MP4 scan in `epub_mp4.rs` and indexes local sample ranges with the locked MP4 demuxer. It checks AVC parameter sets before allowing the in-process decoder to allocate pictures. Coded frames are bounded to an area of 1920 × 1088 pixels, and reference and reorder buffers are bounded to 16 pictures. Each call may feed up to 512 access units while seeking and waiting for a frame. The adapter drives the decoder in sample decode order, checks each frame against the sorted composition timestamps, and applies a continuous MP4 edit and the requested clip to the output intervals. It converts progressive 8-bit and 10-bit planar YUV 4:2:0, 4:2:2 and 4:4:4 to packed RGB8 using the declared matrix and range. The decoder output must keep the sample layout from the validated sequence parameter set. The adapter rejects PQ and HLG transfer characteristics and carries the pixel aspect ratio separately. The iterator emits one owned frame at a time. The existing AAC-LC adapter opens the same packaged MP4 source for audio. Both endpoints take presentation microseconds so the caller can schedule them on one clock. [OxideAV H.264 decoder](https://github.com/OxideAV/oxideav-h264)

`epub_theora.rs` indexes packets from the same bounded Ogg page validator used by Opus. It checks Theora headers, keyframe positions and frame indices, limits coded area before allocation, and uses the locked OxideAV Theora decoder for pictures. Its RGB conversion shares the video adapter and applies the Theora crop window and pixel aspect ratio. Each logical stream has a constant frame rate, with at most 512 frames of keyframe preroll. In an Ogg chain with a soundtrack, each segment advances the shared clock at the audio sample rate by the greater of its picture and soundtrack durations, rounding the picture duration up to a whole sample for the next segment start. Audio fills intermediate gaps with silence. Video emits frames only for their presentation intervals. [Theora specification](https://www.theora.org/doc/Theora.pdf), [OxideAV Theora decoder](https://github.com/OxideAV/oxideav-theora)

`epub_structure.rs` stages a replacement spine and manifest additions. It retains original itemrefs, assigns unique paths and IDs to new chapters, and shares the editor’s ZIP writer. `epub_toc_edit.rs` updates EPUB 3 navigation and EPUB 2 NCX in the same transaction. If an EPUB 3 spine also points to a compatibility NCX, the editor updates it from the same selected spine entries. Navigation groups keep their hierarchy and use each group’s earliest surviving spine target for sibling ordering. Omitted chapters stay in the manifest and archive so references from other chapters or media overlays can still resolve. New SVG spine chapters are fixed-layout and use the standalone SVG media type. A staged archive read resolves their stylesheets and raster resources through the SVG renderer before return. New and replaced local assets are bounded, and the completed archive is parsed again before return. The structure editor shares the chapter replacement preflight and stages chapter properties, markup, navigation and SMIL edits before checking references. Reorder staged navigation markup supplied as a spine chapter replacement or as an explicit replacement of the packaged EPUB 3 navigation resource outside the spine. For explicit resource replacement, validate the final navigation entries against the final manifest and archive and check retained links to IDs removed by the replacement or reorder. Regenerate a compatibility NCX from its own hierarchy when the spine changes. The NCX input can be the staged resource replacement. Assign shared play-order numbers to repeated destinations across the primary map and auxiliary lists. Sort spine destinations by their final spine position and match distinct fragments in one document against staged XML IDs. Preserve encounter order for destinations outside the spine and for legacy fragment IDs that are missing. Validate its primary map, targets in auxiliary lists and previously referenced element IDs even when the XHTML navigation supplies the exposed table of contents. Packaged SVG replacement uses the same removed-ID check as chapter replacement and reads the staged manifest and references, including newly inserted chapters. Stage supplemental XHTML in the resource map. Reject spine entries, effective fallback chapters, and documents hyperlinked from the spine or navigation there. A supplemental edit updates its manifest flags and validates the final contents with the chapter extractor, including archive-local hyperlinks, embedded documents and fragment IDs. Insert hyperlinked auxiliary documents with `linear="no"` and require a linear chapter in edited orders. Chapter replacement preserves the existing media type and reuses anchor validation for XHTML and SVG. Fixed chapters keep a numeric viewport or viewBox.

`epub_output.rs` projects supported semantic blocks into the existing WordCraft model. The WordCraft web layout handles unstyled reflowable previews. The native DOCX and PDF exporters handle document pagination in the semantic profile. The bounded `epub_math.rs` adapter substitutes an equation object at each formula's original text span and lets the pinned math engine shape it.

## Creation and dependency scope

`EditableEpub` validates and escapes semantic EPUB 3 source, then calls rbook 0.7.12 with only its write feature. Writes run through a bounded sink. The public creation APIs do not accept externally supplied XHTML, OPF, or archive entry names. Authoring and metadata editing use the same output limit. Input, output, XML and resource limits bound the work of individual stages. They do not measure total process memory.

This design replaces LexePub and retains the existing rbook writer. It requires no craft-libs EPUB proposal or change to the shared backend revision. The read and creation paths are independently exercised by round-trip tests.

Container limits, repeated metadata, namespace preservation, links, table spans, and image handling are owned by the local reader. The existing writer accepts a bounded sink and publication dates at its current pin.

## Source rendition

`epub_spine_edit.rs` stages bounded attribute edits by original occurrence. It updates `linear` and the supported rendition property groups using source ranges, retaining other attributes and property tokens. The structure planner inserts edited itemrefs into the reordered spine or patches existing slots when the order stays the same. Chapter replacement checks the effective edited layout and preserves the viewport requirements of any other fixed occurrence of the same resource. Final extraction validates changed layouts and supplies viewport evidence. Navigation and content members remain byte-identical during an itemref-only edit. A separate bounded access check starts from linear sections, navigation and the package guide for newly non-linear EPUB 3 resources. It follows local hyperlinks through XHTML, SVG and supported XHTML frame sources, resolves spine fallback aliases, and checks decoded IDs before accepting fragment targets. A frame contributes its links as a source. Reaching an auxiliary chapter requires a navigation link or a linear occurrence of the same resource. A disconnected cycle provides no route from the primary reading order.

Source rendering reads the original target resource to retain CSS selector context and author geometry. `epub_css.rs` loads and parses local styles with Raffia and resolves the supported selectors under a work budget. It indexes rules by a required ID, class, or tag in the subject compound. Candidate rules still use the full selector matcher, and cascade priorities retain original rule order. `epub_style.rs` maps the cascade and inherited typography onto Taffy and native WordCraft properties. `epub_layout.rs` shapes text and math, measures and lays out boxes, then paints the composed draw list through the native renderer. SVG content documents and embedded images use the validated static profile and resvg. Embedded SVG is rasterized with transparency in its layout box. Semantic DOCX and PDF export use PNG for the static SVG image. Styled reflowable chapters use the existing 80,000-point paint coordinate limit. The renderer checks the requested raster region against the shared DPI and pixel limits before building the draw list. For clipped packaged-font text it measures unhinted control-point bounds once per font, variation instance, size and glyph. It conservatively accounts for synthetic slant, bold and raster rounding before emitting outlines. The bounds cache and native outline measurement have independent limits. The original draw budget still protects full previews and uncached outlines.

The EPUB adapter owns author stylesheet resolution and knows only archive paths. It never delegates fetching to a renderer. Raffia, Taffy and resvg are locked crates with permissive licensing. `epub_fonts.rs` registers bounded local fonts in a chapter-owned Parley collection. It uses WordCraft's existing web-font decoding and bundled fallbacks, without adding faces to its process-wide font database. For ranged XHTML faces, the adapter intersects the font's character map with the CSS ranges in a bounded in-memory copy. It uses the existing locked `write-fonts` package to write the effective map, including covered variation sequences, and preserves the original packaged bytes. Parley tries equal-style faces in reverse declaration order. The adapter preserves the ordered named and generic families on each styled text run and registers author faces under private family names to keep scoped glyph coverage separate from bundled names. Parley tries the specified XHTML families before the bundled fallback. Mixed text remains shaped around image and native equation boxes. Tables using packaged fonts derive cell placements and spans from the validated semantic table grid. `epub_obfuscation.rs` recognizes the IDPF font-only declaration and applies it to preview reads after verifying the targets against the package manifest. Resource reads return the stored bytes.

`epub_css_logical.rs` maps horizontal flow-relative longhands to physical layout inputs using the element's CSS direction and HTML direction hint. The selector cascade retains the declaration index alongside importance, specificity and rule order. It chooses one winner for each physical slot before substituting its variable, so an invalid winning substitution cannot revive a losing physical declaration. Ancestor layout values retain resolved absolute font-relative lengths for explicit inheritance and stay bounded by XML depth. `epub_css_calc.rs` evaluates the existing Raffia math tree for bounded scalar, length and percentage arithmetic and for min(), max() and clamp(). Typed comparisons, stepped values and sign-related expressions share the per-chapter layout calculation table and count against its node budget. The evaluator keeps percentage dependencies in scalar intermediates such as sign(), even when the final length has no percentage coefficient. Font units resolve during style computation, while the sign or step uses the receiving box during layout. Constant scalars simplify immediately. The CSS trig evaluator uses degrees for typed angles and radians for unitless forward-function inputs. It carries relative atan2 operands and their bounded inverse-angle result to layout. Exact cardinal angles avoid spurious residual lengths. Tangent at an asymptote and a deferred tangent whose bound crosses an asymptote return explicit errors. Deferred powers and logarithms use conservative scalar intervals to establish a finite layout range before registering with Taffy. For a typed Euclidean norm, the triangle inequality bounds the absolute and percentage terms independently while the full expression evaluates against the receiving box. A step with a zero interval carries NaN through the expression and yields zero at the CSS math boundary. Division by a scalar that still depends on layout and literal non-finite constants return explicit errors. Explicit inheritance carries a handle to the parent's computed expression so it can use the child's containing box without recomputing font units. It resolves font and viewport units to points and keeps the percentage coefficient for layout. The chapter-owned tree implements Taffy's public layout traits and passes a bounded calculation table to its existing block, flex, grid and out-of-flow algorithms. It preserves percentage terms whose coefficients cancel to zero, so a mixed height still follows the indefinite-height rules. For table tracks, a width or height that mixes a percentage with a nonzero length uses automatic sizing. Physical and logical declarations share a calculation after the cascade. `epub_css_grid.rs` preserves function boundaries from Raffia's component values and projects supported fixed, intrinsic, flexible, minmax and fit-content tracks into Taffy. A counted repeat expands to at most 32 tracks per axis in total. Inherited tracks keep their computed font units and evaluate percentages against the receiving grid during layout. Invalid track grammar follows the CSS cascade. The projection carries case-sensitive names from bracket groups into the native row and column line maps. A repeated group merges the names at its shared boundaries without counting one line twice for an occurrence. The placement longhands and their shorthands retain cascade priorities, resolve variables and forward named or indexed lines and spans to Taffy. Named area templates require equal row widths and filled rectangular regions. Template inheritance keeps the names and resolved track sizing together. Each explicit template is limited to 32 tracks per axis, 128 line names per axis, 128 bytes per name and a magnitude of 64 for explicit placement indices and spans. The grid-template shorthand expands area strings, row sizes and column tracks into explicit longhands before the cascade. Omitted area row sizes become auto and adjacent closing and opening names share the boundary. The grid shorthand also sets or resets the independent implicit track and auto-flow properties, which the native layout uses for row or column placement and dense gap filling. Implicit track cycles are limited to 32 authored track sizes per axis. Automatic repetition and subgrids return an explicit unsupported error. [CSS grid track sizes](https://www.w3.org/TR/css-grid-2/#track-sizing) [CSS grid placement](https://www.w3.org/TR/css-grid-2/#line-placement) [CSS grid shorthands](https://www.w3.org/TR/css-grid-2/#explicit-grid-shorthand) The HTML direction resolver uses the locked Unicode bidi data and excludes independently directed subtrees during a first-strong scan. It starts the styled XHTML path when an HTML direction hint appears, including chapters without stylesheets. Vertical writing still returns an explicit error for logical geometry. [HTML directionality](https://html.spec.whatwg.org/multipage/dom.html#the-dir-attribute) [CSS logical property groups](https://www.w3.org/TR/css-logical-1/#box) [CSS trigonometry and exponential functions](https://www.w3.org/TR/css-values-4/#trig-funcs)

Preferred horizontal-flow box sizes use Taffy's intrinsic dimensions. A fit-content inline size with a definite limit resolves through bounded min-content and max-content probes of the same box. This gives the authored intermediate width when the wrapped text occupies a shorter line. The functional limit follows box-sizing, and the keyword uses the available margin-adjusted space. Native leaf layout measures text inside the content box and reports the outer extent including padding and borders. Column flex resolves the preferred cross width before measuring wrapped content height. Mixed limits reuse the chapter calculation table and preserve their sizing function through inheritance. Intrinsic minimum and maximum constraints and contain-fit sizing return an explicit error. [CSS intrinsic sizing](https://www.w3.org/TR/css-sizing-3/#sizing-values) [Functional fit-content](https://www.w3.org/TR/css-sizing-4/#sizing-values)

Sibling-position selectors use Raffia's An+B arguments and count only qualifying element siblings. Type-relative functions compare expanded names. Child filter lists use the existing scoped complex matcher and add their highest specificity. Each visited sibling shares the stylesheet work budget, including non-element nodes. [Sibling-position selectors](https://www.w3.org/TR/selectors-4/#child-index)

Styled inline direction scopes use the CSS and HTML Unicode bidi control pairs in a private layout buffer. Its offsets account for the synthetic boundaries when laying out links, inline images and equations. Forced breaks close and reopen the active scopes. The Parley path handles surrounding text with the same native bidi algorithm and PDF capture omits formatting controls from searchable clusters. Public extraction retains the source text and offsets. [CSS bidi control translation](https://www.w3.org/TR/css-writing-modes-3/#bidi-control-codes)

`epub_frame.rs` resolves iframe and typed XHTML object resources against the staged manifest and validates their static markup. The layout engine renders each child with its own viewport, CSS cascade, and transparent background. Nested rendering shares limits of 32 frames, six levels, 32 million frame pixels and 128 MiB of archive reads. The extractor keeps original XHTML bytes and inventories local hyperlink destinations. The fixed-layout PDF collector translates clipped child text and links into the host page and rebases child links against the original archive path. Semantic export rasterizes the child viewport and rejects linked frames when link preservation is required.

`epub_svg.rs` applies the shared EPUB cascade to SVG prolog stylesheets and embedded declarations in source order. It sends only supported presentation properties and same-document paint references to resvg. SVG images carry their archive resolution base independently of the original markup and public image name. The renderer supplies PNG or JPEG resources through a bounded in-memory resolver. The SVG font database is scoped to the rendition and registers packaged fonts under their CSS family names. External resolvers for file and data URLs are disabled. `epub_svg_use.rs` checks each use target against an ID in the same SVG subtree and measures the expanded tree before usvg creates instances. It rejects duplicate targets and cycles, and bounds expanded nodes, referenced-subtree visits, payload bytes and depth. The renderer repeats the measurement after applying CSS so computed style bytes are counted in each instance. usvg handles instance geometry, viewport sizing and presentation inheritance. [SVG use elements](https://www.w3.org/TR/SVG2/struct.html#UseElement)

`epub_svg_effects.rs` validates same-document linear and radial gradient templates against unique IDs and limits each template chain to 32 references. usvg resolves inherited gradient stops and geometry. A filter can include up to 16 Gaussian blur, drop-shadow, color matrix, flood, offset, composite, merge, blend, component-transfer, morphology, convolution, image, tile, turbulence and displacement primitives. A merge may have up to 16 inputs. Unspecified input uses SourceGraphic for the first primitive and the preceding result thereafter. Explicit references select SourceGraphic, SourceAlpha or a unique earlier named result in the same filter. The adapter checks both composite and blend inputs and every merge input before usvg can substitute a different input. It normalizes flood color and opacity and bounds matrix and arithmetic coefficients, channel tables and transfer coefficients, filter-region geometry, scaled blur deviations and offsets. Component transfer supports identity, table, discrete, linear and nonnegative-exponent gamma modes. A transfer accepts one function per channel and a table accepts up to 64 entries. After usvg expands instances, the adapter charges the isolated layer and each native pass, including merge input copies, per-channel gamma evaluation, morphology neighborhoods, convolution taps and wrap work, the tile seed copy and output, noise setup and octaves, and branches unused by the last result. The layer limit is 8 Mi pixels and the weighted work limit is 32 Mi pixels per SVG raster. Visual rendering uses the native result. PDF capture classifies the actual final dependency graph of each group. A chain retaining source coverage uses the source placement. A chain confined to the ink of one native painted source is sampled using the same alpha-coverage path as SVG clips and masks. Affected glyphs, enclosing links and destinations use the surviving ink. An offset chain with a single source lineage can transport source geometry through one native filter layer. The adapter uses the native device transform decomposition and truncates each offset on that layer's raster grid before mapping the displacement back into SVG coordinates. Blend keeps the union of its two input alpha coverages. Alpha transfer classification checks whether a curve retains nonzero alpha and whether it leaves transparent input clear. Color matrix and component-transfer stages can restrict alpha when a single painted source can be measured, including before or after a verifiable offset. Alpha-preserving translations can move the common source geometry of several objects. Ownership is prepared before XHTML layout and sampled after the final raster size is known. Translated layers replay with the full renderer viewport so source pixels can move into view. Inner clips are sampled in their transported position and outer clips stay in the layer's output position. Nested offset layers can move one painted source when each participating native layer has positive axis-aligned device scales and its final result follows a single source lineage. The capture adds the independently rounded offsets and samples the outermost isolated layer that still has one painted source with the full renderer viewport. This keeps intermediate filter crops, clips, masks and enclosing opacity in their original raster domain. Geometry of a container uses its already-processed output layer bounds. A rotated, sheared or reflected offset stack can use exact alpha replay when its enclosing layer contains one painted graphic or one verified native text cluster. Capture carries each normalized renderer raster and the accumulated map back to the page, rounding offsets in the grid where each primitive runs. The whole native layer supplies the surviving source bounds, including antialiasing and intermediate crops. The replay checks that canceling the public node renderer’s origin normalization preserves the original transform. Shared affine stacks can attribute two to eight branches, each with one graphic or verified Unicode cluster, through up to four common offset layers. The final lineage of each layer must carry source alpha through signed offsets and optional RGB-only color or transfer stages. The adapter encloses local path control points and stroke joins before transforming their bounds, then enlarges the resulting footprints to include native raster support and rounding in every active layer. It rejects touching projected supports and samples each branch from the original shared alpha replay. Affine stacks with multiple glyph clusters in a branch, intersecting supports, separately filtered branches in the same isolated context, near-singular transforms, and unresolved spatial combinations remain unproven. Such branches block capture only when an affected request needs their geometry. Morphology uses the native component-wise erosion and dilation kernels with bounded radii and device work. Omitted or nonpositive radii retain the input through a native zero-deviation pass, including the named result and primitive region. Erosion in a proven single-source axis-aligned filter chain samples the outermost isolated raster context. Dilation can retain annotations on the original ink when the output covers it. Native convolution validates bounded signed 9 × 9 kernels, targets, bias, divisor and edge modes. It uses the renderer’s device-pixel grid. Authored kernelUnitLength returns an unsupported error because the locked engine does not apply it. The rendered copy supplies a nonzero effective divisor when the source omits the divisor or sets it to zero. A wider-precision sum keeps small nonzero defaults from rounding to zero in the native parser. The packaged SVG keeps the authored value. The adapter charges every tap across the transformed layer and bounds the additional native work of negative wrap indices against a one-pixel input. Its PDF coverage proof tests the kernel tap aligned with the original pixel after rotating the kernel, the signs of the other taps relative to the divisor, and the bias. Alpha-preserving convolution can remain in a named offset chain. For neighborhood-based reductions that cannot paint outside the source, the capture samples native alpha from one painted source on a positive axis-aligned grid. Filter images and ordinary SVG images share the archive-relative PNG/JPEG resolver and its resource, placement, encoded and decoded bounds. The resolver supplies normalized in-memory PNG bytes to usvg. The native fitter handles primitive-region alignment and clipping. An authored image-rendering presentation value is carried into the renderer’s CSS representation when the SVG cascade has no override. Native measurement charges each realized filter image for decoding and painting, including instances made by use and repeated coverage draws. Unrelated image pixels use the same PDF attribution restrictions as repeated tiles. They can provide a single-source alpha mask or sit under provable original source paint. Native tiling follows explicit or implicit prior named filter results. The adapter follows offsets to the effective seed region and verifies that the seed is already sRGB, because the native tile kernel places the copied bytes in an sRGB buffer. The seed must fit inside both the filter and rendered viewport so native clipping cannot remove or shift part of a repeat. A smaller seed uses whole device-pixel periods on both axes. The renderer applies the native repeat shader at the seed origin and clips to the output primitive region. A full-filter seed remains in-place and can participate in a verified offset chain. The PDF dependency classifier tracks copied output through named stages and the compositing order. It can retain original source drawn on top of copies or measure a tiled alpha mask on one painted source. Direct attribution to repeated or covering copies remains unproven. Turbulence and displacement use user-space primitive units and the native sampler. The adapter bounds both noise lattice coordinates and octaves before rasterizing. Turbulence supports deterministic unstitched noise and fractal noise. Displacement validates both named inputs and bounds the signed transformed scale. Zero displacement preserves the first input geometry. Source-retaining final compositions keep their original geometry, and source-shaped procedural masks use native alpha from a proven single-source context. Other source-replacing noise and spatial remapping remain unproven for capture. Filtering inside a pattern, mask or clip path is unsupported. XHTML parses literal CSS `font-variation-settings` with Raffia, inherits or clears the axis list through the cascade and supplies the resulting coordinates to Parley. Automatic optical sizing sets `opsz` from the font size in points when the author has not supplied that axis. The renderer draws glyph outlines at the normalized coordinates returned by shaping. SVG previews pass the corresponding stylesheet properties through to resvg. For families with packaged variation descriptors, the adapter also associates each authored request with a private family alias so the native font resolver can distinguish requests that map to the same discrete native values.

The XHTML and SVG cascades compute unregistered custom properties on each element before substituting var() in supported declarations. Case-sensitive names, the inherited computed values, dependencies inside fallbacks, and shorthand cascade order are preserved. Each declaration, dependency depth and chapter-wide substitution work is bounded. SVG still checks resolved paint values before passing them to resvg. [CSS custom properties](https://www.w3.org/TR/css-variables-1/)

SVG rendering registers the same bounded Unicode-restricted font copies used for XHTML. A document-scoped resolver matches native style, weight, and stretch, and keeps the author's ordered family list for each selected face. Equal descriptors prefer later matching packaged declarations. Fallback faces exclude characters covered by earlier candidates so the SVG shaper keeps preferred glyphs even when a later face could render the entire span. Font bytes, faces, stack counts and matching work have explicit bounds.

If native fallback leaves a missing glyph or an author face needs custom axis coordinates, the adapter can retry the source text as separate font runs. It chooses a face for each Unicode grapheme cluster and lets the same SVG engine place and shape the resulting runs. For packaged variable faces, the renderer clamps weight, width and slant to the matched descriptor ranges, then applies the face’s explicit defaults, automatic optical sizing and the element’s own settings. A single run can keep the original element and its textLength. The renderer validates retained glyphs after the retry. For mixed faces with a root textLength, the adapter measures one horizontal solid-fill chunk after native shaping. In spacingAndGlyphs mode it scales the inline extent around the native anchor. In the default spacing mode it distributes the difference between native clusters in logical order. It verifies the resulting advance width, unchanged glyph shapes and font settings, and the exact movement of each glyph relative to the anchor. The adjusted native tree drives preview, searchable PDF text, and link and fragment capture. Spacing-only adjustment requires unambiguous native clusters and no authored letter or word spacing. For the locked left-to-right shaper, a cluster’s final glyph carries its Unicode label. Preceding unlabeled marks belong to the same cluster when the font and complete logical sequence agree. The fitter verifies the same movement for all member glyphs, and PDF capture includes their ink in one labeled cluster. Ambiguous or reordered clusters remain outside the spacing profile. A nested tspan that owns the whole measured chunk uses the same fitter as its containing text element. Up to 64 independently positioned sibling tspan owners per text element can receive spacing-only adjustment. One bounded probe tree measures an isolated copy of each owner and verifies the same original glyphs, native chunk and positions. The final layout verifies every adjusted cluster translation and keeps unadjusted siblings in place. A single direct tspan may expand inside an outer spacing-only textLength. One native probe measures the child while the original mixed-face chunk measures the full text. The adapter accepts only an unkerned, undecorated, left-to-right chunk with unambiguous addressable characters and isolated child glyphs that match the original after translation. It fits the child first and translates that whole child as one unit for the parent’s spacing. Cumulative relative positions carry both adjustments into the native tree, which must preserve font and outline transforms and reach the final outer width. For one horizontal chunk, the outer text may supply bounded user-unit or px dx and dy lists. A companion native layout omits those lists. The verifier matches both layouts against the same logical character sequence and checks cumulative shifts, the leading anchor, width, order, face selection and every glyph transform. Spacing moves whole clusters. SpacingAndGlyphs composes a horizontal scale about the authored x plus the leading dx and verifies the resulting transform against the fitted tree. Nonzero offsets inside a shaped cluster and position streams with reordered glyphs, a non-axis-aligned transform, or an ambiguous character mapping return explicit errors. Other overlapping length owners, scaling one chunk beside siblings, rotations, descendant position lists, reused text, non-solid paint, strokes, and text-local effects can return explicit unsupported errors when the retry is required. [CSS Fonts matching algorithm](https://www.w3.org/TR/css-fonts-4/#font-matching-algorithm), [SVG text layout](https://www.w3.org/TR/SVG2/text.html#TextLayoutAlgorithm)

For XHTML, the font collection registers packaged variants for the chapter's requested weight, width and slope when the author defines an oblique face, a weight range or a width descriptor. Width matching filters candidates first. XHTML families with an oblique descriptor then compare signed angle ranges using the CSS directional preference. Parley and Fontique match the remaining descriptors and resolve the winning face for each run, including Unicode fallback. A second shaping pass applies each selected face's clamped weight, width and slant, followed by its explicit axis defaults, optical sizing and the element's own variation settings in that order. `epub_audio.rs` maps SMIL time bounds to half-open sample-frame intervals. Streaming advances that integer cursor using PCM frames returned by the decoder.
