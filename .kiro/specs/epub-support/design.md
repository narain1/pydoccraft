# EPUB design

## Container and package

The in-repo reader uses the existing shared ZIP preflight and locked rust libraries for ZIP and XML. The preflight bounds central directory work and checks local/central consistency before indexing. The EPUB layer compares the archive readers' entry views, opens the single declared package, then bounds each resource read and the cumulative read budget. Paths use `/` and resolve only inside the publication. Runtime operations are in-process and offline.

`epub.rs` owns the OPF metadata, manifest and spine, EPUB 3 navigation and EPUB 2 NCX, and guarded resource I/O. `epub_content.rs` maps namespace-aware XHTML onto ordered document blocks. Tables carry semantic cells with nested blocks, spans, headings and row-group metadata. Images retain source bytes, alternative text and inline position. SVG uses a restricted static profile. MathML extraction retains a namespace-complete source fragment and readable text from the primary presentation branch. `epub_overlay.rs` reads each referenced SMIL timing tree once, resolves local text and audio paths, and validates target IDs when their XML members are parsed.

## Public API and output

The existing native extraction, render, and conversion operations dispatch to EPUB. Python also exposes bounded resource ranges and ordered per-chapter media cues. Cue audio points to packaged bytes and uses integer microseconds for clip timing. The timing tree preserves sequence scope and semantic roles. The Python binding uses `epub_audio.rs` to decode one cue at a time, keeping a decoder for the current track. WAVE reads seek directly to the selected PCM samples. MP3 and AAC keep codec state and the last decoded frame for adjacent cues. MP3 restarts for backward seeks and AAC warms up the preceding access units when seeking. `epub_aac.rs` bounds MP4 boxes and sample-table expansion before demux, validates the resulting local access unit ranges, and applies a continuous edit list to the presentation time. Playback yields each target's audio or text and uses blocking sinks with active-target callbacks to synchronize highlighting.

`epub_editor.rs` handles targeted OPF metadata updates and batch XHTML and SVG replacements. It stages changes and resolves repeated spine positions to their shared file. When a replacement removes an element ID, the editor checks hyperlinks in the staged replacements and retained content documents, including non-spine resources, navigation, the package guide and compatibility NCX. It checks retained overlay targets from the parsed timing trees. Links to previously missing IDs stay as authored. The editor rebuilds the ZIP through the bounded sink. The chapter editor validates the complete tentative book before returning its bytes. Untouched members keep their uncompressed content, with archive header details subject to the writer.

`epub_media.rs` collects XHTML audio and video references in the page metadata under the existing semantic output budget. It resolves local sources, posters, and caption tracks against the package manifest and archive. The inventory retains remote URLs without opening them. An element's src attribute takes precedence over child source options. Codec hints and package media types identify playback candidates. The Python API tries local candidates in authored order and advances to the next on an unsupported codec or profile. Audio streams through the native decoder and chunk reader used for SMIL. The XHTML preview uses the existing image path for packaged posters and otherwise displays authored fallback content. The chapter editor checks retained media references with its XML dependency scan and supports WebVTT and TTML resources. Styled timed-text rendering remains open. [HTML media elements](https://html.spec.whatwg.org/multipage/media.html)

`epub_video.rs` reuses the bounded MP4 scan in `epub_mp4.rs` and indexes local sample ranges with the locked MP4 demuxer. It checks AVC parameter sets before allowing the in-process decoder to allocate pictures. Coded frames are bounded to an area of 1920 × 1088 pixels, and reference and reorder buffers are bounded to 16 pictures. Each call may feed up to 512 access units while seeking and waiting for a frame. The adapter drives the decoder in sample decode order, checks each frame against the sorted composition timestamps, and applies a continuous MP4 edit and the requested clip to the output intervals. It converts progressive 8-bit and 10-bit planar YUV 4:2:0, 4:2:2 and 4:4:4 to packed RGB8 using the declared matrix and range. The decoder output must keep the sample layout from the validated sequence parameter set. The adapter rejects PQ and HLG transfer characteristics and carries the pixel aspect ratio separately. The iterator emits one owned frame at a time. The existing AAC-LC adapter opens the same packaged MP4 source for audio. Both endpoints take presentation microseconds so the caller can schedule them on one clock. [OxideAV H.264 decoder](https://github.com/OxideAV/oxideav-h264)

`epub_theora.rs` indexes packets from the same bounded Ogg page validator used by Opus. It checks Theora headers, keyframe positions and frame indices, limits coded area before allocation, and uses the locked OxideAV Theora decoder for pictures. Its RGB conversion shares the video adapter and applies the Theora crop window and pixel aspect ratio. Each logical stream has a constant frame rate, with at most 512 frames of keyframe preroll. In an Ogg chain with a soundtrack, each segment advances the shared clock at the audio sample rate by the greater of its picture and soundtrack durations, rounding the picture duration up to a whole sample for the next segment start. Audio fills intermediate gaps with silence. Video emits frames only for their presentation intervals. [Theora specification](https://www.theora.org/doc/Theora.pdf), [OxideAV Theora decoder](https://github.com/OxideAV/oxideav-theora)

`epub_structure.rs` stages a replacement spine and manifest additions. It retains original itemrefs, assigns unique paths and IDs to new chapters, and shares the editor’s ZIP writer. `epub_toc_edit.rs` updates EPUB 3 navigation and EPUB 2 NCX in the same transaction. If an EPUB 3 spine also points to a compatibility NCX, the editor updates it from the same selected spine entries. Navigation groups keep their hierarchy and use each group’s earliest surviving spine target for sibling ordering. Omitted chapters stay in the manifest and archive so references from other chapters or media overlays can still resolve. New SVG spine chapters are fixed-layout and use the standalone SVG media type. A staged archive read resolves their stylesheets and raster resources through the SVG renderer before return. New and replaced local assets are bounded, and the completed archive is parsed again before return. The structure editor shares the chapter replacement preflight and stages chapter properties, markup, navigation and SMIL edits before checking references. Reorder staged navigation markup supplied as a spine chapter replacement or as an explicit replacement of the packaged EPUB 3 navigation resource outside the spine. For explicit resource replacement, validate the final navigation entries against the final manifest and archive and check retained links to IDs removed by the replacement or reorder. Regenerate a compatibility NCX from its own hierarchy when the spine changes. The NCX input can be the staged resource replacement. Assign shared play-order numbers to repeated destinations across the primary map and auxiliary lists. Sort spine destinations by their final spine position and match distinct fragments in one document against staged XML IDs. Preserve encounter order for destinations outside the spine and for legacy fragment IDs that are missing. Validate its primary map, targets in auxiliary lists and previously referenced element IDs even when the XHTML navigation supplies the exposed table of contents. Packaged SVG replacement uses the same removed-ID check as chapter replacement and reads the staged manifest and references, including newly inserted chapters. Stage supplemental XHTML in the resource map. Reject spine entries, effective fallback chapters, and documents hyperlinked from the spine or navigation there. A supplemental edit updates its manifest flags and validates the final contents with the chapter extractor, including archive-local hyperlinks, embedded documents and fragment IDs. Insert hyperlinked auxiliary documents with `linear="no"` and require a linear chapter in edited orders. Chapter replacement preserves the existing media type and reuses anchor validation for XHTML and SVG. Fixed chapters keep a numeric viewport or viewBox.

`epub_output.rs` projects supported semantic blocks into the existing WordCraft model. The WordCraft web layout handles unstyled reflowable previews. The native DOCX and PDF exporters handle document pagination in the semantic profile. The bounded `epub_math.rs` adapter substitutes an equation object at each formula's original text span and lets the pinned math engine shape it.

## Creation and dependency scope

`EditableEpub` validates and escapes semantic EPUB 3 source, then calls rbook 0.7.12 with only its write feature. Writes run through a bounded sink. The public creation APIs do not accept externally supplied XHTML, OPF, or archive entry names. Authoring and metadata editing use the same output limit. Input, output, XML and resource limits bound the work of individual stages. They do not measure total process memory.

This design replaces LexePub and retains the existing rbook writer. It requires no craft-libs EPUB proposal or change to the shared backend revision. The read and creation paths are independently exercised by round-trip tests.

Container limits, repeated metadata, namespace preservation, links, table spans, and image handling are owned by the local reader. The existing writer accepts a bounded sink and publication dates at its current pin.

## Source rendition

`epub_spine_edit.rs` stages bounded attribute edits by original occurrence. It updates `linear` and the supported rendition property groups using source ranges, retaining other attributes and property tokens. The structure planner inserts edited itemrefs into the reordered spine or patches existing slots when the order stays the same. Chapter replacement checks the effective edited layout and preserves the viewport requirements of any other fixed occurrence of the same resource. Final extraction validates changed layouts and supplies viewport evidence. Navigation and content members remain byte-identical during an itemref-only edit. A separate bounded access check starts from linear sections, navigation and the package guide for newly non-linear EPUB 3 resources. It follows local hyperlinks through XHTML, SVG and supported XHTML frame sources, resolves spine fallback aliases, and checks decoded IDs before accepting fragment targets. A frame contributes its links as a source. Reaching an auxiliary chapter requires a navigation link or a linear occurrence of the same resource. A disconnected cycle provides no route from the primary reading order.

Source rendering reads the original target resource to retain CSS selector context and author geometry. `epub_css.rs` loads and parses local styles with Raffia and resolves the supported selectors under a work budget. It indexes rules by a required ID, class, or tag in the subject compound. Candidate rules still use the full selector matcher, and cascade priorities retain original rule order. `epub_style.rs` maps the cascade and inherited typography onto Taffy and native WordCraft properties. `epub_layout.rs` shapes text and math, measures and lays out boxes, then paints the composed draw list through the native renderer. SVG content documents and embedded images use the validated static profile and resvg. Embedded SVG is rasterized with transparency in its layout box. Semantic DOCX and PDF export use PNG for the static SVG image. Styled reflowable chapters use the existing 80,000-point paint coordinate limit. The renderer checks the requested raster region against the shared DPI and pixel limits before building the draw list. For clipped packaged-font text it measures unhinted control-point bounds once per font, variation instance, size and glyph. It conservatively accounts for synthetic slant, bold and raster rounding before emitting outlines. The bounds cache and native outline measurement have independent limits. The original draw budget still protects full previews and uncached outlines.

The EPUB adapter owns author stylesheet resolution and knows only archive paths. It never delegates fetching to a renderer. Raffia, Taffy and resvg are locked crates with permissive licensing. `epub_fonts.rs` registers bounded local fonts in a chapter-owned Parley collection. It uses WordCraft's existing web-font decoding and bundled fallbacks, without adding faces to its process-wide font database. For ranged XHTML faces, the adapter intersects the font's character map with the CSS ranges in a bounded in-memory copy. It uses the existing locked `write-fonts` package to write the effective map, including covered variation sequences, and preserves the original packaged bytes. Parley tries equal-style faces in reverse declaration order. The adapter preserves the ordered named and generic families on each styled text run and registers author faces under private family names to keep scoped glyph coverage separate from bundled names. Parley tries the specified XHTML families before the bundled fallback. Mixed text remains shaped around image and native equation boxes. Tables using packaged fonts derive cell placements and spans from the validated semantic table grid. `epub_obfuscation.rs` recognizes the IDPF font-only declaration and applies it to preview reads after verifying the targets against the package manifest. Resource reads return the stored bytes.

`epub_css_logical.rs` maps horizontal flow-relative longhands to physical layout inputs using the element's CSS direction and HTML direction hint. The selector cascade retains the declaration index alongside importance, specificity and rule order. It chooses one winner for each physical slot before substituting its variable, so an invalid winning substitution cannot revive a losing physical declaration. Ancestor layout values retain resolved absolute font-relative lengths for explicit inheritance and stay bounded by XML depth. The HTML direction resolver uses the locked Unicode bidi data and excludes independently directed subtrees during a first-strong scan. It starts the styled XHTML path when an HTML direction hint appears, including chapters without stylesheets. Vertical writing still returns an explicit error for logical geometry. [HTML directionality](https://html.spec.whatwg.org/multipage/dom.html#the-dir-attribute) [CSS logical property groups](https://www.w3.org/TR/css-logical-1/#box)

`epub_frame.rs` resolves iframe and typed XHTML object resources against the staged manifest and validates their static markup. The layout engine renders each child with its own viewport, CSS cascade, and transparent background. Nested rendering shares limits of 32 frames, six levels, 32 million frame pixels and 128 MiB of archive reads. The extractor keeps original XHTML bytes and inventories local hyperlink destinations. The fixed-layout PDF collector translates clipped child text and links into the host page and rebases child links against the original archive path. Semantic export rasterizes the child viewport and rejects linked frames when link preservation is required.

`epub_svg.rs` applies the shared EPUB cascade to SVG prolog stylesheets and embedded declarations in source order. It sends only supported presentation properties and same-document paint references to resvg. SVG images carry their archive resolution base independently of the original markup and public image name. The renderer supplies PNG or JPEG resources through a bounded in-memory resolver. The SVG font database is scoped to the rendition and registers packaged fonts under their CSS family names. External resolvers for file and data URLs are disabled. `epub_svg_use.rs` checks each use target against an ID in the same SVG subtree and measures the expanded tree before usvg creates instances. It rejects duplicate targets and cycles, and bounds expanded nodes, referenced-subtree visits, payload bytes and depth. The renderer repeats the measurement after applying CSS so computed style bytes are counted in each instance. usvg handles instance geometry, viewport sizing and presentation inheritance. [SVG use elements](https://www.w3.org/TR/SVG2/struct.html#UseElement)

`epub_svg_effects.rs` validates same-document linear and radial gradient templates against unique IDs and limits each template chain to 32 references. usvg resolves inherited gradient stops and geometry. A filter can include up to 16 Gaussian blur, drop-shadow, color matrix, flood, offset, composite and merge primitives. A merge may have up to 16 inputs. Unspecified input uses SourceGraphic for the first primitive and the preceding result thereafter. Explicit references select SourceGraphic, SourceAlpha or a unique earlier named result in the same filter. The adapter checks both composite inputs and every merge input before usvg can substitute a different input. It normalizes flood color and opacity and bounds matrix and arithmetic coefficients, filter-region geometry, scaled blur deviations and offsets. After usvg expands instances, the adapter charges the isolated layer and each native pass, including merge input copies and branches unused by the last result. The layer limit is 8 Mi pixels and the weighted work limit is 32 Mi pixels per SVG raster. Visual rendering uses the native result. PDF capture classifies the actual final dependency graph of each group. A chain retaining source coverage uses the source placement. A chain confined to the ink of one native painted source is sampled using the same alpha-coverage path as SVG clips and masks. Affected glyphs, enclosing links and destinations use the surviving ink. An offset chain with a single source lineage can transport source geometry through one native filter layer. The adapter uses the native device transform decomposition and truncates each offset on that layer's raster grid before mapping the displacement back into SVG coordinates. Non-spatial color matrix stages can change alpha when a single painted source can be measured. Alpha-preserving translations can move the common source geometry of several objects. Ownership is prepared before XHTML layout and sampled after the final raster size is known. Translated layers replay with the full renderer viewport so source pixels can move into view. Inner clips are sampled in their transported position and outer clips stay in the layer's output position. Stacked filter layers and result paths with unresolved spatial combinations remain unproven. Such branches block capture only when an affected request needs their geometry. Filtering inside a pattern, mask or clip path is unsupported. [SVG gradient templates](https://www.w3.org/TR/SVG2/pservers.html#LinearGradientElement), [SVG filter primitives](https://www.w3.org/TR/filter-effects-1/)

XHTML parses literal CSS `font-variation-settings` with Raffia, inherits or clears the axis list through the cascade and supplies the resulting coordinates to Parley. Automatic optical sizing sets `opsz` from the font size in points when the author has not supplied that axis. The renderer draws glyph outlines at the normalized coordinates returned by shaping. SVG previews pass the corresponding stylesheet properties through to resvg. For families with packaged variation descriptors, the adapter also associates each authored request with a private family alias so the native font resolver can distinguish requests that map to the same discrete native values.

The XHTML and SVG cascades compute unregistered custom properties on each element before substituting var() in supported declarations. Case-sensitive names, the inherited computed values, dependencies inside fallbacks, and shorthand cascade order are preserved. Each declaration, dependency depth and chapter-wide substitution work is bounded. SVG still checks resolved paint values before passing them to resvg. [CSS custom properties](https://www.w3.org/TR/css-variables-1/)

SVG rendering registers the same bounded Unicode-restricted font copies used for XHTML. A document-scoped resolver matches native style, weight, and stretch, and keeps the author's ordered family list for each selected face. Equal descriptors prefer later matching packaged declarations. Fallback faces exclude characters covered by earlier candidates so the SVG shaper keeps preferred glyphs even when a later face could render the entire span. Font bytes, faces, stack counts and matching work have explicit bounds.

If native fallback leaves a missing glyph or an author face needs custom axis coordinates, the adapter can retry the source text as separate font runs. It chooses a face for each Unicode grapheme cluster and lets the same SVG engine place and shape the resulting runs. For packaged variable faces, the renderer clamps weight, width and slant to the matched descriptor ranges, then applies the face’s explicit defaults, automatic optical sizing and the element’s own settings. A single run can keep the original element and its textLength. The renderer validates retained glyphs after the retry. For mixed faces with a root textLength, the adapter measures one horizontal solid-fill chunk after native shaping. In spacingAndGlyphs mode it scales the inline extent around the native anchor. In the default spacing mode it distributes the difference between native clusters in logical order. It verifies the resulting advance width, unchanged glyph shapes and font settings, and the exact movement of each glyph relative to the anchor. The adjusted native tree drives preview, searchable PDF text, and link and fragment capture. Spacing-only adjustment requires unambiguous native clusters and no authored letter or word spacing. Nested lengths, per-glyph positioning, reused text, non-solid paint, strokes, and text-local effects remain explicit unsupported cases when that retry is required. [CSS Fonts matching algorithm](https://www.w3.org/TR/css-fonts-4/#font-matching-algorithm)

For XHTML, the font collection registers packaged variants for the chapter's requested weight, width and slope when the author defines an oblique face, a weight range or a width descriptor. Width matching filters candidates first. XHTML families with an oblique descriptor then compare signed angle ranges using the CSS directional preference. Parley and Fontique match the remaining descriptors and resolve the winning face for each run, including Unicode fallback. A second shaping pass applies each selected face's clamped weight, width and slant, followed by its explicit axis defaults, optical sizing and the element's own variation settings in that order. Alternate registrations share their font bytes. The XHTML paint style keeps the exact requested oblique angle when the shaping engine rounds its synthetic skew. The outline painter uses the fractional shear and preserves the native glyph positions and advances. For angles below one degree, it checks the selected face's style and whether the shaper uses a variable slant or italic axis. Shears must fit the existing paint geometry budget. Each chapter is limited to 512 packaged face variants and each paragraph to 8 MiB of face-specific variation spans. [CSS font matching](https://www.w3.org/TR/css-fonts-4/#font-matching-algorithm), [Variation precedence](https://www.w3.org/TR/css-fonts-4/#feature-variation-precedence)

SVG use instances inherit font family, weight, width, signed style, optical sizing and axis settings from their host chain. When custom properties are used in supported SVG styles, the adapter matches the archive stylesheet and inline cascade with the referenced root as the selector boundary. The shared variable resolver pushes an instance layer above the host's computed values and restores the host scope after each branch. Private templates reuse the same source, inherited font request and active variable scope. Native use still places and scales the template. Local paint references within each clone follow its renamed paint servers, and private IDs map to authored fragment and text link ownership. Selector work, variable values and dependency depth, source and expanded XML, and SVG font stacks have explicit limits. Additional SVG features, semantic fixed-layout conversion and complex text fallback remain open. [SVG use inheritance](https://www.w3.org/TR/SVG2/struct.html#UseStyleInheritance)

`epub_svg_object_links.rs` recovers graphics link ownership and destination IDs stripped by native use expansion. A bounded second native parse tags source groups with unique opacity values and verifies that the resulting paint leaves have the original geometry, order and transforms. The adapter matches each tagged leaf range to the original painted subtree and measures that subtree with the original alpha, clipping and mask coverage. The probe does not contribute pixels to the PDF. It reports an explicit error if the drawing geometry changes or a tagged range cannot be attributed to the original tree. Directly drawn fragment targets keep precedence. When only reused copies are visible, the first painted instance supplies the destination. Repeated PDF page selections still map same-chapter links to their own occurrence. [SVG hyperlink targets](https://www.w3.org/TR/SVG2/linking.html#LinksOutOfSVG)


## Presentation MathML

`epub_math.rs` projects bounded Presentation MathML to the pinned WordCraft equation model for layout and export. The equation envelope carries root size and foreground, and OMML runs carry inherited size, foreground and variant. Presentation and syntax nodes share a projection budget. Each tensor pair contributes one native script level to the depth guard, including levels generated for prescripts. Variable fences and separators use explicit math runs when the native delimiter cannot hold the full sequence.

Extraction and native equation projection share a token whitespace normalizer. It drops container indentation from extracted text and collapses XML whitespace inside tokens. Nonbreaking spaces remain literal. The MathML source remains available with its indentation and annotations. The large-sample check uses the existing semantic output limits. [MathML whitespace rules](https://www.w3.org/TR/MathML3/chapter2.html#fund.collapse)

The EPUB stylesheet cascade resolves declarations on the source chapter before detaching an equation. Equation descendants use a sparse style map with a 64 MiB accounting limit, separate from the 8,000-box style limit. Annotation subtrees are inert. The preview and export paths attach a bounded snapshot of the supported declarations and the enclosing font size and foreground. The equation projector applies those declarations over same-element presentation hints and evaluates relative sizes in the equation's inherited context. Fixed-layout previews use the chapter viewport. The semantic export path applies these styles within equations. Public extraction retains the original MathML markup.

WordCraft represents zeroed `mpadded` metrics with its visible phantom node. Horizontal `mspace` uses a sized math-space run and follows native script scaling. The emitted OMML retains that run. Centered fractions with a default rule or no rule use the existing native equation model.

The custom fraction adapter lays out both operands with WordCraft, using an invisible phantom to reserve the opposite operand's box in each pass. This preserves the native fraction style, axis, and glyph sizing. The adapter places the operands using the requested alignment and resizes the native rule around its center. It moves the operands apart when a thicker rule needs more clearance. A thinner rule retains the native operand positions. The resulting glyphs and rule compose with other operators and follow the existing parent script scaling. [MathML fraction attributes](https://www.w3.org/TR/MathML3/chapter3.html#presm.mfrac), [MathML Core fractions](https://www.w3.org/TR/mathml-core/#fractions-mfrac)

`epub_math_table.rs` projects spanning tables and tables with authored spacing or alignment onto bounded grids of up to 128 rows and 32 columns each. The measured path applies row and column spacing lists, table alignment lists, and row and cell overrides. It aligns the whole table or a selected row with the containing equation. Equal tracks use the largest per-track requirement after removing the gaps inside each span. Explicit fixed columns keep their widths, and spans can grow the automatic columns they cover. A definite table width resolves percentage columns, reserves the frame and gaps, and measures automatic tracks before dividing remaining space equally among fitted tracks. When fitted tracks are absent, remaining width expands automatic tracks. Spans that include a fitted track must fit their final allocated widths. Widths that would clip cell content or conflict with equal-column sizing return an explicit error. Percentage and unitless table widths resolve against the containing line width for transparent MathML groups. Preview defers shaping width-dependent text until Taffy supplies a definite content width and paints the measured result for the final box. Native reflow uses the page text width or the content width of a fixed XHTML table cell. Nested relative tables can use the width of a containing MathML cell when every track in its span is independently determined. The projector scopes the sum of those tracks and their internal gaps to the cell. Known widths include fixed tracks, equally sized tracks with a known width, fitted tracks with no intrinsic automatic tracks, and a lone automatic track that receives a known remainder. Intrinsic cells and intervening operands without their own measured width return an explicit error. Solid and dashed rules are measured in the row and column gaps and around frames. A shared occupancy map interrupts a rule wherever the same spanning cell lies on both sides. Frames reserve the authored inline and block spacing. Bounded rectangle segments preserve dashed rules in previews and PDF. Standalone ruled tables project to Word table and cell borders with the same merge interruptions and editable equations. DOCX requires clearance for its top and bottom border bands. Ruled grids inside equations require the PDF export path. Positive row numbers count from the top and negative ones from the bottom. Ordinary matrices with native column justification use the pinned matrix layout directly. The span map rejects overlapping cells and row spans past the last row. The projector retains a native export path when a nested spanning table is the sole expression in its containing cell. It shares the formula depth and node budgets across all grids. The node budget includes implicit grid entries materialized by native export. The grid uses the pinned equation shaper for ordinary cells and the nested grid's width, height and baseline for table cells. The renderer draws each grid inside its containing inline box. A standalone table that fits the available export page becomes a native merged table with editable equations and native nested tables in its cells. PDF retains searchable cell text. For DOCX grids inside formulas or mixed with paragraph text, Office Math matrix slots retain each editable cell expression and hidden placement guides reproduce the measured spans. Matrix rows contain ordinary slots, so the recorded placement stays fixed during later edits. The adapter calibrates native row and column spacing through the pinned equation shaper. When columns are tighter than a native multi-column matrix permits, adjacent single-column matrices carry the exact cell expressions at their measured positions. The private placement marker lets extraction reconstruct the logical row and column order. It bounds the generated native node count and omits the placement guides from normalized DOCX text. [MathML 3 table geometry](https://www.w3.org/TR/MathML3/chapter3.html#presm.mtable), [MathML table cell spans](https://www.w3.org/TR/mathml-core/#entry-in-table-or-matrix-mtd), [Office Math matrices](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.math.matrix?view=openxml-3.0.1)


MathML labeled rows contribute their first cell to a separate label track and use the remaining cells in the regular bounded span map. In an auto-width table, two equal margins reserve the maximum label width and the minimum label gap. This keeps the data grid centered when `side` switches. Labels share their row’s vertical alignment and can override it through their own cell. Only data tracks participate in equal-column sizing, spans, rules and frames. The editable DOCX projection reserves both margins as native equation tracks, including in a split matrix. It retains the label content as an editable expression. Overlap sides and authored whole-table widths stay unsupported. Labeled grids with table rules use the preview and PDF path because the editable equation track projection has no native borders. [MathML 3 labeled rows](https://www.w3.org/TR/MathML3/chapter3.html#presm.mlabeledtr)

`epub_math_compose.rs` measures spanning grids and padding boxes before handing them to the native equation shaper. The adapter gives WordCraft independently calibrated phantom extents and a private position marker for each measured box. WordCraft lays out the enclosing operator tree. The adapter substitutes each box's positioned glyphs and rules at the resulting baseline and script scale. Guide colors are chosen outside the author's formula colors. The adapter bounds saved drawing items and rejects oversized native extents. Small positive dimensions are subject to the pinned native one-point run-size floor. MathML 3 padding can set or adjust width, ascent and descent using lengths, percentages and content-relative pseudo-units. Signed horizontal and vertical offsets move the ink independently of the padded metrics. Vertical mspace dimensions contribute to the line box. [MathML 3 padding](https://www.w3.org/TR/MathML3/chapter3.html#presm.mpadded), [MathML Core spacing](https://www.w3.org/TR/mathml-core/)

For semantic PDF export, WordCraft paginates the paragraphs with the reserved equation boxes. The EPUB adapter finds each composed equation by its source paragraph and object index, including placements within table cells and clipped layout groups. It substitutes the measured glyphs and vector rules in the corresponding equation layout. WordCraft writes the resulting layout with searchable glyph text. The adapter verifies that each composed equation has a placement and bounds the measured and substituted drawing data.

For DOCX, the adapter replaces supported `mpadded` boxes with native WordCraft equation nodes before writing. Fixed widths use a visible zero-width phantom for the original operand and a sized math space for the box advance. Additive widths leave the operand's native width intact and divide the extra advance between leading and trailing sized spaces. Content-relative dimensions use the original operands’ native measurements. Replaced ascent and descent use the matching phantom flags on the original operand. Invisible zero-width Office Math phantoms reserve the new extents for padding and vertical spaces. The adapter calibrates those extents to the native shaper at DOCX half-point run-size resolution. DOCX extraction omits the generated guides. The native tree retains fractions, radicals and nested padding throughout a paragraph or in an editable table cell. Offsets beyond an additive width use a zero-width visible phantom and reserve the padded advance separately. A one-row Office Math equation array uses a hidden extent guide to place its content above or below the axis inherited from the reopened DOCX paragraph. An outer phantom replaces the array’s extents with the requested padding metrics. Extraction omits the generated guides and the placement array while retaining the operands and operators. Negative left offsets still require the composed PDF path.

## WebM playback

`epub_webm.rs` bounds the EBML tree and physical blocks before opening the pinned Matroska demuxer. It checks nesting, element extents, track and packet counts, and compressed block sizes. It reconciles demuxed packets with the physical block order, including audio laces. Unknown-size segments and clusters can end at the enclosing boundary. A WebM asset carries one segment, and each playback endpoint selects a single track of its media type. An explicit WebM ordinal counts declarations of the selected media type in track order and includes unsupported codecs. The demuxer still validates the bounded transport of the surrounding streams. The playback adapters check the selected track and use its existing presentation clock. SMIL track selection is a per-resource playback option.

`epub_webm_video.rs` checks VP8 and VP9 frame headers, geometry and show flags before sending packets to the corresponding native decoder. VP9 superframes can carry invisible reference frames. The retained picture intervals use WebM timestamps and explicit or default frame durations. A seek decodes from the nearest preceding keyframe before yielding the clipped intervals.
