# Python API migration inventory

Run `python tools/python_api_inventory.py > /tmp/opencode/python-api-inventory.json` from the repository root. The JSON is a reproducible, source-derived inventory, not a promise that every named class is exported by `doc_ex`: `__init__.exports` identifies the declared root exports; public classes in private modules include return types and annotation types reachable through the facade. Each class records bases, decorators, annotated fields, assigned instance attributes, method signatures and decorators; each function/method records syntactic calls and direct `_core` references. Properties, setters and overloads are separate entries. Source line numbers permit inspection. This avoids importing the native extension or executing document code.

## Migration dependency map

* Root facade (`src/doc_ex/__init__.py`): source/path/stream reading, limits, format detection, aliases, extraction, conversion, page selection, payload decoding and native-error translation. Migrate these behaviors as well as exported signatures. `open` owns native render sessions for PDF and Office, while EPUB uses eager extraction; cleanup on failed construction matters.
* Read API (`_document.py`, `models.py`): documents, pages, collections and value models; text/dict/JSON/Markdown/HTML, images, links, semantic/nested tables, stories, search, rendering, conversion and format-specific operations. Preserve ordering, coordinates, negative indexing, image placement, escaping, bounded exports and exact serialization. Models returned from extraction own their data; page/document close behavior differs from independent values. Native render sessions must be released exactly once, including exceptional paths.
* Authoring (`_authoring.py`): `new`, measurement helpers, EPUB, PDF, DOCX and PPTX editable document families and the many returned nested views, collections, ranges, shapes, fields, tables, formatting and option TypedDicts. The inventory includes these public declarations even when absent from root `__all__`. Follow each factory and collection return type, inheritance and calls, including private helper chains; direct `_core` references alone are not a complete dependency graph. Preserve save/export, reopen and conversion semantics and format-specific capability errors.
* Errors (`errors.py`): retain public exception hierarchy, mapping and distinction between invalid arguments, unsupported features, malformed input, limits and closed state. Do not expose raw native failures or silently drop content.
* Boundaries and safety: preserve input/archive, selected-page, text, export, rendering, recursion and native resource limits; do not bypass validation through alternate constructors. Values accepted via Python protocols (index, numeric, iterable, path and stream) and callback/reentrancy behavior require tests, not signature comparison alone.

## Ownership and validation gates

Use existing `tests/` as behavioral inventory, in particular `*ownership*`, `*lifetime*`, `*limits*`, `*callbacks*`, `*safety*`, `test_input_bounds.py`, `test_reference_inventory.py`, rendering, authoring and format-specific tests. Views/ranges/collections must retain their owner when needed, reject stale/deleted or cross-document objects as currently specified, and not keep closed sessions alive accidentally. Test mutation after obtaining views, deletion, parent close, garbage collection, callback exceptions and reentrancy; do not assume all returned values have the same ownership policy.

For each migration unit compare the generated inventories before and after, then test signatures, defaults, properties/setters, overloads, iteration/indexing, exceptions, ownership and round trips against existing tests and representative PDF/DOCX/PPTX/EPUB files. Reopen generated outputs and test both extraction and rendering where supported. Run the locked Rust and installed-wheel validation prescribed by `AGENTS.md`; record results in the relevant spec when integrating the migration. An inventory match is necessary but not sufficient proof of behavioral compatibility.

## Coverage limitations

This is a conservative static declaration inventory, not dynamic reachability or a compatibility verifier. It includes non-root public declarations and excludes private declarations except selected protocol methods. It does not discover dynamically installed attributes, inherited members on each subclass, generated dataclass methods, conditional definitions, aliases, monkey patches, types or defaults imported from elsewhere, native-only members, or all Python protocols. Calls are syntactic, include nested scopes, and do not resolve aliases, dispatch, indirect helper chains, runtime validation or error semantics. Instance-attribute assignments are approximate. Inspect private helpers, `_core`/Rust dispatch, stubs if added, docs, examples and tests separately. A changed source tree changes output; no baseline is asserted by this tool.
