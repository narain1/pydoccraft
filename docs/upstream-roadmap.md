# Upstream ArtCraft contribution register

This register marks where format behavior belongs. It is a source audit and contribution proposal, not runtime validation, a claim that every feature is absent, or a request to file issues in upstream repositories. Only this repository's roadmap is being published. Upstream upgrades remain dedicated changes with the full dependency/license/corpus audit.

**Evidence states:** existing public support; verified gap in an inspected path; candidate requiring further audit. Public support still needs local integration, safety and fidelity tests. Shared needs do not automatically belong in `craft-libs`: place work where the responsible implementation already lives.

## Work that stays local

Python naming, typed convenience values, source/path/stream handling, owned extraction models, Markdown formatting, recipes, published support tables, and API compatibility belong here. Rust adapters own native error mapping, operation dispatch, normalized offsets, boundary limits and our PNG encoding metadata. Upstream should own shared document-format semantics, layout and writer algorithms. If a candidate turns out to be already supported, reclassify it as integration/validation work instead of filing a redundant upstream request.

## Additional pinned-source evidence: styles, slide text and Markdown

WordCraft public style resolution, overlays and native paragraph/range editing support named paragraph/character styles and explicit overrides; this is local adapter/API work, not a missing upstream feature. DeckCraft public `edit::{insert,delete,format,text_range,props_at}` and Hyperlink/Action values support rich ranges and URL/SlideId targets, including native PPTX serialization and PDF navigation. Adapters validate offsets because the native edit functions clamp inputs, and guard dangling slide targets because the writer can omit them. No engine crate or upstream revision change is needed.

Portable Markdown media packaging is Python projection over owned extracted values; it is not an upstream format writer. It shares the existing Markdown/HTML fallback and retains source diagnostics. The next PPTX table audit confirms stored row heights are minimums expanded by public rendering layout; exact-height authoring must not be inferred from a numeric model field.

## Section and table adapter findings

WordCraft public section enumeration/mutation, part creation and native clone-on-write blocks support independent section stories without copying relationship serialization. The pinned layout treats NextColumn as a page transition; that start remains unavailable locally, and a public column-transition layout implementation is upstream work. Mixed-size continuous transitions are also rejected explicitly. General linked headers and unequal columns are not implied by the independent-section profile.

DeckCraft public table grid mutations support the local merge/split/insert/delete profile. Its public renderer expands minimum row heights; exact height must not be advertised. `deckcraft_render::table::look` resolves inherited table styles but its module is private: a bounded public resolved-cell-style accessor is a useful upstream candidate for inspection. Local explicit-border editing does not need a new library API.

## Grid and geometry findings

WordCraft public row deletion removes the row without repairing a removed vertical-merge anchor; inserted rows can retain continuation properties. A public fallible span-preserving grid edit is an upstream candidate. The local adapter currently rejects orphan continuations atomically. General rich fragment copy also needs upstream note/comment/bookmark identity remapping before supporting semantic row cloning.

PdfCraft page-box transforms, text colors and effective geometry are publicly available and integrated locally. ContentTruncated and outline_more signals now cause explicit local failures; finer caller-configurable inspection budgets remain upstream work.

## Notes and owned PDF fields

WordCraft's lower-level native parts, NoteRef objects and section NoteProps support creation and layout of footnotes/endnotes without engine dependencies. Complete paired-anchor deletion and cross-document fragment copying still need a public semantic mutation API: the current native generic delete only balances content controls, and fragment copy collects text-box parts without remapping note/comment/bookmark identities. Local authoring guards reject destructive anchored edits. Public control value/display synchronization and lock validation should move out of engine commands before FORM3 is implemented; constructing model variants alone would not satisfy editable-control behavior.

U02/U07 note conversion uses public [Document::convert_notes](https://github.com/storytold/wordcraft/blob/f2e15cf8f899a79899a2d9595ca4ce7df1e5ea22/crates/doc/src/edit.rs#L163), which preserves part IDs and updates reference kinds and standard note styles across stories. Its [reference-style update](https://github.com/storytold/wordcraft/blob/f2e15cf8f899a79899a2d9595ca4ce7df1e5ea22/crates/doc/src/edit.rs#L203) swaps an entire run's style when that run contains a converted marker. Raw-native regression `upstream_note_conversion_restyles_whole_shared_reference_run` demonstrates ordinary text and an unconverted reference changing from red to blue in both PNG and PDF. The adapter rejects only mixed-content standard-style runs and retains marker-only/custom-style controls. Upstream should make the semantic operation change reference-local styles without restyling unrelated content; no local run-repair algorithm is added. This remains separate from note deletion and fragment remapping.

PdfCraft's public forms crate supports creation, typed filling, deletion and appearances; existing edit flatten supports verified appearance preservation. The local integration uses a bounded, script-free owned profile: single-widget text/checkbox/choice fields and immutable same-page radio groups. Arbitrary imported-field traversal needs a fallible caller-bounded API. Appearance generation should report overflow explicitly: current autosizing floors at four points and multiline output can omit trailing lines. The local profile uses fixed font size, native Helvetica width checks and complete-appearance postconditions; arbitrary widget lifecycle and safe removal of an empty AcroForm remain separate integration/audit work.

## Redaction and table fidelity audit

PDF7 is blocked on strict native removal semantics: pinned PdfCraft redaction retains partially intersecting vector operators behind clipping, can retain clip-and-paint geometry and clips shadings without comprehensive residual reporting. Its verification checks glyph/inline-image residue, not complete vector recoverability; stream decoding also lacks configurable aggregate limits. A nonzero paths-clipped guard alone cannot make this safe. Request strict removal, comprehensive residual/unsupported reporting and operation-wide resource limits upstream before exposing secure redaction. No redaction dependency or API has been added.

WordCraft public native table measurement/fitting is usable, but measurement stops after 4,000 direct paragraphs and must be preflighted. Cell spacing and complete shared-edge border conflict resolution still need upstream model/layout work. DOCX table alternative-text title/description are modeled, while PDF Table/TR/TH/TD tagging and visible caption association are not established. These remain distinct from local direct formatting integration.

The U02/TBL7 shading source audit distinguishes supported solid fills from missing native semantics. Existing cell `background` and whole-table/conditional `Style.format(background=...)` already provide solid appearance, inheritance and reset. Direct [TableProps.shading](https://github.com/storytold/wordcraft/blob/f2e15cf8f899a79899a2d9595ca4ce7df1e5ea22/crates/doc/src/props.rs#L999) is [serialized](https://github.com/storytold/wordcraft/blob/f2e15cf8f899a79899a2d9595ca4ce7df1e5ea22/crates/docx/src/write/props.rs#L445), but [cell fill selection](https://github.com/storytold/wordcraft/blob/f2e15cf8f899a79899a2d9595ca4ce7df1e5ea22/crates/layout/src/table.rs#L493) consults only direct cell shading and resolved style fill; neither direct table shading nor row-property-exception shading participates. This is not a missing whole-table-style fill API. [Cell shading](https://github.com/storytold/wordcraft/blob/f2e15cf8f899a79899a2d9595ca4ce7df1e5ea22/crates/doc/src/props.rs#L1128) and [conditional style fill](https://github.com/storytold/wordcraft/blob/f2e15cf8f899a79899a2d9595ca4ce7df1e5ea22/crates/doc/src/styles.rs#L226) store optional RGB; the [reader](https://github.com/storytold/wordcraft/blob/f2e15cf8f899a79899a2d9595ca4ce7df1e5ea22/crates/docx/src/read/props.rs#L130) resolves theme colors rather than retaining editable theme identity, and the [cell writer](https://github.com/storytold/wordcraft/blob/f2e15cf8f899a79899a2d9595ca4ce7df1e5ea22/crates/docx/src/write/props.rs#L568) emits solid RGB shading. Patterns, editable theme fills and explicit transparent cancellation need native model/read/write/layout support. [Style overlay](https://github.com/storytold/wordcraft/blob/f2e15cf8f899a79899a2d9595ca4ce7df1e5ea22/crates/doc/src/styles.rs#L241) treats absent fill as inheritance, so existing `None` remains reset/inherit, not a transparent override. Do not duplicate these APIs or implement native table shading by silently painting every cell.

Conditional table styles are supported by public `Style::table_part`/`set_table_part` and `StyleSheet::table_style` resolution, so their local API integration requires no upstream engine or revision change. Remaining targeted upstream work includes conditional paragraph properties beyond alignment, column band widths greater than one, patterned fills and full shared-edge border conflict resolution. Whole-table style fill renders natively; the direct table-property shading gap above is separate. The pinned [region_borders](https://github.com/storytold/wordcraft/blob/f2e15cf8f899a79899a2d9595ca4ce7df1e5ea22/crates/layout/src/table.rs#L318) maps conditional vertical edges into per-cell `left`/`right`, but [interior edge selection](https://github.com/storytold/wordcraft/blob/f2e15cf8f899a79899a2d9595ca4ce7df1e5ea22/crates/layout/src/table.rs#L515) subsequently reads the cleared `inside_v`; row-region inside-vertical and interior-facing column/corner borders disappear in both PNG and PDF despite serialized definitions. Explicit nil suppression is also lost. The adapter rejects these conditional assignments while permitting resets and direct/whole-table controls. Native regression `upstream_conditional_vertical_borders_are_serialized_but_dropped` bypasses that guard and preserves model/readback, placed-rule and visible-output evidence; fix the upstream selector rather than rebuilding border resolution locally.

The related U02/BG7 page-border finding is **source-only, with no executed reproduction yet**. Public [section page borders](https://github.com/storytold/wordcraft/blob/f2e15cf8f899a79899a2d9595ca4ce7df1e5ea22/crates/doc/src/section.rs#L734) store a border group without an offset mode. [Native layout](https://github.com/storytold/wordcraft/blob/f2e15cf8f899a79899a2d9595ca4ce7df1e5ea22/crates/layout/src/lib.rs#L1651) measures spacing from the physical page edge, while the [section writer](https://github.com/storytold/wordcraft/blob/f2e15cf8f899a79899a2d9595ca4ce7df1e5ea22/crates/docx/src/write/story.rs#L1352) hardcodes `w:offsetFrom="text"`; the [reader](https://github.com/storytold/wordcraft/blob/f2e15cf8f899a79899a2d9595ca4ce7df1e5ea22/crates/docx/src/read/props.rs#L691) does not retain that distinction. [Border serialization](https://github.com/storytold/wordcraft/blob/f2e15cf8f899a79899a2d9595ca4ce7df1e5ea22/crates/docx/src/write/props.rs#L160) also rounds spacing to whole points and clamps it to 0–31. Before offering page-border formatting, a raw native fixture with asymmetric nonzero margins must compare serialized offset mode, public placed-rule coordinates, reader/writer retention and PNG/PDF output. This is a targeted consistency candidate under existing ownership, not an observed cross-application rendering failure. No adapter XML rewrite or coordinate compensation is proposed.

PdfCraft native reading-order glyphs and line/text APIs support exact contiguous multiline annotation labels. The local adapter can connect this provenance to surviving normalized blocks without a new reading-order engine. Ambiguous overlaps, noncontiguous selections and labels inside inferred tables remain explicitly unresolved; this does not establish quadpoint grouping or semantic table-link support upstream.

All three pinned renderers expose native region primitives: PdfCraft `RenderRequest.tile`, WordCraft `render_region` and DeckCraft render offsets/size. Their local integration requires validation around native rounding/clamping, not a new rasterizer. Faithful transparency/background control needs upstream work: PDF rendering clears white and reading-color options alter content paint; WordCraft paints page color/paper, and DeckCraft paints the slide background. These are distinct from document background authoring.

Imported PDF field enumeration remains incomplete at the pinned APIs. Render inspection silently stops deep field trees, flattens multiple choice values to text and exposes only one widget. Forms enumeration has a deeper silent cutoff and skips unknown kinds without caller-supplied aggregate field/widget/string/option limits. Request a fallible bounded enumeration API with explicit completion/error, inherited typed values, every widget identity and unknown-kind reporting. Adapter postchecks after unbounded enumeration cannot establish safe complete inspection.

WordCraft tab stops, leaders and native line/page/column break markers are available in public model/layout/writer APIs. Keep their 64-stop serialization limit explicit. Bar tabs need native rendering support; current layout treats them as left tabs without drawing a bar. A native decimal-tab placement fixture shows the segment right edge at the stop and the decimal point displaced left; authoring decimal stops is rejected until native layout aligns the decimal separator correctly. Locale-aware separators and page/column break semantics inside cells/auxiliary stories need separate native evidence. Next-style metadata is public, while automatic next-style application on Enter remains in excluded editor command code; move that operation to a lower-level public library before promising editor behavior.

Next/linked style metadata and document character/paragraph defaults are local adapter work using public `Style.next`, `Style.linked`, `StyleSheet.default_chr/default_para/default_para_present` and native resolvers. They do not require a new upstream style API. The separate serialized default-kind style flag is not a reliable default-style selector at this pin because resolution falls back to `Normal`; arbitrary fallback selection needs upstream resolver work. Default edits still require local atomic geometry/tab validation.

WordCraft document defaults need consistent absent-size semantics: the public resolver falls back to 11pt, but the DOCX reader materializes 10pt when `docDefaults` omits size. A native regression preserves this mismatch; local default-size clearing is rejected atomically while explicit sizes and other supported clears roundtrip. Built-in Heading1–Heading9 also point to absent HeadingNChar companions. Upstream should either define those character styles or omit dangling links; local reads fail explicitly and clearing/replacing the link repairs it without creating invented styles.

PdfCraft drawing needs collision-safe resource allocation. Native stamps replace `PCHelv`, text drawing replaces `PCFHelvetica`, backgrounds use rounded `PCGS` names, and images derive `PCImg` names from object numbers. Imported documents can already bind those names to different resources. Reproductions show original text/image pixels or opacity changing after a new draw. The adapter stages edits and verifies existing effective inherited bindings before commit, rejecting unsafe replacements; public `pdfcraft_model::pages` supplies inheritance. A public allocator should preserve all existing names and distinguish exact opacity values rather than rounding them into colliding keys.

WordCraft pagination places an oversized unsplittable row intact when already at the top of a fresh page, even beyond the physical page. A 24-line fixture on a 300pt page emits its final PDF line around y353–365. Public placed-cell geometry permits a local serialization guard for unmerged non-splitting, exact-height and repeated-header rows. Complete merged-row overflow handling and a fallible bounded paginator remain upstream candidates; intentionally clipped exact-height content inside a page is a different behavior.

PdfCraft public AddedText/AddedImage support local bounded text areas, native wrapping/alignment and visual image crop/quarter-turns/flips. AddedText height does not constrain painting, so local metric overflow validation is required. Native wrapping repeatedly measures growing strings and repeats layout during drawing; the adapter bounds a conservative work estimate before entering those paths. Supplied-font wrapping and strict glyph-outline text clipping still need a suitable public native placement API. Image crop fractions are silently clamped to 0..0.45 upstream; local validation rejects values outside that range. Visual cropping retains original media.

WordCraft paragraph borders are public and share native rendering across body, cells and stories. Four outer edges are local adapter work. Between borders serialize but are omitted by push_para; no bar model exists. The shared border renderer substitutes triple→double and dot_dash→dashed, clamps widths below0.25pt and thick below1.5pt, draws vertical double strokes on top of each other, and emits empty vertical wave paths. Native regression fixtures preserve these gaps. Local DOCX border authoring rejects the affected styles/widths/orientations rather than accepting a different visual result; horizontal double/wave remain available. Native paragraph inheritance replaces the whole border group, distinct from table per-side resolution.

PdfCraft full-font reuse searches only 256 `PCFull`-prefixed resources, then 8,192 objects. A valid imported fixture with 256 prefix bindings and 8,200 earlier reachable objects hides the newly registered program; two explicit text rows embed three full programs while the adapter previously charged once. Tests retain the native reproducer and boundary controls. Local supplied-font drawing rejects the unprovable prefix profile before embedding; upstream should return/reuse an explicit registered font-program handle or provide bounded lookup with completion reporting.

## PDF underlay and Form composition audit
