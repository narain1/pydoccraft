This development guide describes the 0.3.1 baseline and explicitly marked unreleased work. EPUB support is unreleased. See the [validation record](../.kiro/specs/rust-document-engine/validation.md) for tested artifacts.

The [operation evidence matrix](support-matrix.md) separates reading, creation, authored/imported editing, preservation, rendering and export for explicitly audited profiles. It links all roadmap criteria and records historical artifact evidence without claiming complete parity.

## PDF

PDF support is backed by pinned PdfCraft 0.9.0 crates.

### Extracted data

- Pages in source order.
- Reading-order text represented as line-oriented paragraph blocks.
- Text and image bounding boxes in displayed page coordinates.
- Page width, height, rotation, and label.
- Document title, author, subject, keywords, creator, producer, PDF version, encryption state, and tagged state when available.
- URI link destinations and rectangles.
- Non-form images that PdfCraft can export as PNG or JPEG, including width and height.
- Conservative table candidates derived from public positioned reading blocks.

### PDF table detection

PdfCraft 0.9.0 does not expose its internal table detector as a public Rust API. `pydoccraft` therefore uses a small geometry normalizer. It reports a table only when it finds at least two rows and two columns with consistent row alignment, equal column counts, and stable column positions. Text blocks represented by the table are removed from normal paragraph output to avoid duplication.

This deliberately favors false negatives over fabricated tables. Borderless, irregular, spanning, rotated, or visually complex tables may remain plain text.

### PDF links

PdfCraft exposes link destinations, rectangles and text geometry. The adapter recovers unambiguous labels with normalized Unicode character offsets, including repeated labels and contiguous multiline labels, and Markdown attaches those targets inline. Accepted multiline annotations coalesce their consecutive paragraph blocks while retaining native spaces/newlines and unchanged plain text. Neighboring links retain correct offsets. Links inside inferred PDF table cells retain empty labels to avoid duplicating cell text. Overlapping, noncontiguous or ambiguous geometry-only links also retain empty labels and appear in the final **Links** section; the adapter does not infer a reading order across columns or guess omitted glyphs.

### PDF images

Images nested in grouped Form XObjects or encoded in formats the upstream image exporter cannot materialize may be omitted. Extraction is not an inventory of every PDF stream. Rendering remains available even when individual image extraction is unavailable.

### Scanned PDFs

A scan-only page can be rendered but produces no text unless the PDF already contains a text layer. `pydoccraft` contains no OCR engine or model.

## DOCX

DOCX support is backed by pinned WordCraft 0.8.0 crates.

### Extracted data

- Ordered body paragraphs and tables.
- Heading levels resolved through style inheritance and clamped to Markdown levels 1–6.
- Style ID, style name, and outline metadata.
- Resolved numbering definitions and unambiguous native layout labels, separate from paragraph text. See [numbering extraction](numbering-extraction.md).
- Exact hyperlink labels and character offsets.
- Referenced inline and grouped images with bytes, display dimensions, and alt text.
- Semantic tables, including content from nested table cells.
- Anchored comments and replies with author, initials, date, resolved state, and parent identifiers.
- Explicit manual page breaks and inherited `page_break_before` behavior.
- Core document metadata where available, plus bounded supported scalar custom properties.
- Table title/description in `Table.metadata`, separate from visible cell text.

### DOCX properties and field values

`document.metadata["custom"]` maps original property names to strings, booleans, signed 64-bit integers or finite floats for the supported native `lpwstr`, `bool`, `i8` and `r8` kinds. Parsing follows the same strict scalar profile as authored properties; other numeric aliases and structured/raw variants are not coerced. Unsupported kinds, invalid scalar values and ambiguous ASCII-case-insensitive names are omitted with bounded extraction diagnostics. All entries in an ambiguous name group are omitted.

The parsed inventory is capped at 1,024 properties, 64 KiB per value and 256 KiB aggregate raw metadata, including names/kinds. This is a native-model inventory, not a promise of complete source XML preservation: the upstream reader can drop malformed custom parts, omit entries and cap source property traversal before projection. Table alternative text is likewise capped by the upstream reader at 10,000 Unicode characters. Extracted `title`/`description` preserve native absent versus empty values; neither becomes a visible cell caption or a PDF accessibility tag.

Source field text uses stored cached values. Newly authored decimal page/count fields have an empty dirty cache, while PNG/PDF output is evaluated by native layout. General field refresh and convergence remain unsupported.

### DOCX pagination

WordCraft computes layout pages. A paragraph that spans multiple computed pages but contains no explicit page break is emitted once on the first page it occupies because the upstream public model does not expose exact normalized text slices for each laid-out page.

Tables are associated with their first page rather than split into separate normalized table fragments. `Table.rows` retains newline/tab cell text for compatibility; `Table.cells` additionally preserves ordered paragraph/table blocks and horizontal/vertical merge information. Markdown uses HTML for nested, merged, or rich tables. This extraction structure does not provide an editable document model.

Unreferenced files in `word/media/` are not returned.

## PPTX

PPTX support is backed by pinned DeckCraft 0.8.0 crates.

### Extracted data

- One normalized page per slide in presentation order.
- Recursive traversal of grouped shapes with transformed geometry.
- Paragraph and soft-line-break boundaries.
- Run-level URL and resolved internal-slide hyperlinks with exact labels and offsets, including table cells.
- Shape/group URL and resolved internal-slide links.
- Semantic tables and merge metadata.
- Referenced picture bytes, MIME type, alt text, intrinsic dimensions when detectable, and slide placement.
- Speaker notes.
- Comments and nested replies.
- Slide dimensions, name, and hidden state.

Resolved native slide targets use `#page=N` and zero-based `target_page` metadata, including self-links and hidden slides in presentation order. Context-dependent next/previous/first/last/last-viewed actions, end-show, media, custom-show and program actions remain explicit omission diagnostics; they are not treated as fixed page targets. Notes retain their existing text-only link behavior. Unknown action strings and unresolved source relationships can be discarded by the pinned reader before the adapter sees them, so their absence cannot be diagnosed completely without upstream preservation reports.

## Rendering

An open document reuses its native PDF parser or Office model for repeated rendering. DOCX also reuses the completed pagination layout. The public methods and PNG-byte return type are unchanged. Use a context manager or `close()` to release retained models/layouts and private source/password references; already extracted values remain usable. Retention can increase steady-state memory. Native global/thread-local caches and allocator retention are not released by this contract, and calls do not promise parallel rasterization. See [Office measurements and reproduction](office-performance.md).

```python
png = document.render_page(0, dpi=144)
png = document[0].get_pixmap(dpi=144)
detail = document.render_page(0, dpi=300, clip=(36, 36, 144, 72))
```

Both methods return encoded PNG bytes.

- PDF rendering uses PdfCraft pixels and rejects oversized output.
- DOCX rendering uses WordCraft layout and its page renderer.
- PPTX rendering uses DeckCraft slide rendering.
- EPUB renders a fixed chapter in its declared viewport and a reflowable chapter on a scrolling surface 612 points wide.
- `dpi / 72` is used as the native scale.
- DPI must be finite and between 1 and 1200.
- Out-of-range pages are rejected in Python before native dispatch.

DPI controls raster scale and embedded PNG resolution metadata for all three formats. Pixel dimensions follow each engine's rounding; physical resolution uses integer pixels per meter. The multi-DPI corpus checks dimensions, metadata, decoded PNG data and visible content. PDF rotation, crop offsets and UserUnit are covered by the geometry corpus; broader cross-format fidelity remains in the [rendering validation TODOs](../TODO.md#p0--rendering-at-a-requested-dpi).

Each output is bounded to 64 million RGBA pixels in addition to upstream maximum-side limits. DOCX/PPTX dimensions are checked before rasterization; PDF uses upstream oversize rejection. DeckCraft can internally replace a rendering panic with a blank slide. The adapter checks its process-wide panic counter and reports a detected panic as an error for rendering and PDF export. A panic on another thread can cause a spurious error; see the [upstream contract](../AGENTS.md).

Optional `clip=(x, y, width, height)` is available on both methods, including editable document/page/slide wrappers. Coordinates use displayed-page points with a top-left origin; PDF rotation, CropBox and UserUnit are already applied. The rectangle is intersected with the displayed page and snapped outward to its native pixel grid at the requested DPI. Empty intersections, nonfinite values and nonpositive dimensions raise `ValueError`. At page edges, each backend retains its full-page rounding convention; fractional boundaries can add an edge pixel.

Clips use native PdfCraft tiles, WordCraft region rendering and DeckCraft offsets, without allocating a full-page raster first. PDF clips are limited to 4,096 pixels per side and exactly representable tile offsets; Office clips retain the 16,000-pixel side and 64-million-pixel limits. Valid but excessive requests raise the existing resource-limit exception. The returned PNG keeps requested DPI metadata and native page/slide background. Arbitrary background replacement and faithful transparent rendering remain unavailable; clipping does not emulate them by recoloring white pixels. Native parsing/layout still processes the document, so clipping is not selective extraction or a complete memory bound.

Region and full-page rasterization can differ slightly at antialiased edges after native transform translation. The measured PDF text fixture differed by at most two pixels and the fractional-DPI PPTX rectangle by 124 pixels on one edge row, each by at most 1/255 in RGB with identical alpha. Those fixtures use explicit tolerances; full-page/boundary and rotated-PDF shape comparisons remain exact. Fractional PPTX slide edges can retain native partial alpha. These measurements do not establish universal pixel identity or fidelity tolerances for arbitrary effects.

The returned value is not a PyMuPDF `Pixmap`; write it directly or load it with an image library:

```python
from pathlib import Path

Path("page.png").write_bytes(document[0].get_pixmap())
```

## Conversion matrix

| Source | Target | Implementation | Notes |
|---|---|---|---|
| PDF | DOCX | PdfCraft extraction values → `pdfcraft-export` DOCX writer | Positioned text styling and exportable images; not semantic PDF-table conversion |
| DOCX | PDF | WordCraft layout and PDF export | Supports Unicode and tested explicit empty pages |
| PPTX | PDF | DeckCraft PDF export | Slides become PDF pages with a searchable text layer where supported |
| EPUB | DOCX | Semantic EPUB blocks → WordCraft DOCX writer | Reflowable content, with each chapter beginning on a new page |
| EPUB | PDF | Semantic EPUB blocks → WordCraft PDF export | Same content profile as EPUB to DOCX, laid out as printable pages |

DeckCraft PDF export corrupts searchable text for PPTX paragraphs containing explicit breaks; native PDF export of those documents is unsupported until the upstream defect is fixed. A visually correct slide is not evidence that its PDF text layer is correct.

Every other pair—including identity conversions, PDF→PPTX, DOCX→PPTX, and PPTX→DOCX—is rejected explicitly.

```python
import doc_ex

word_bytes = doc_ex.convert("source.pdf", "docx")
pdf_bytes = doc_ex.convert("source.docx", "pdf")
slide_pdf = doc_ex.convert("slides.pptx", "pdf")
```

Conversion is not pixel-perfect. Font substitution, unsupported PDF constructs, Office layout differences, grouped graphics, complex tables, and upstream exporter limitations can change appearance. Always reopen and validate converted output for the intended workflow.

## Document creation

`doc_ex.new("docx" | "pdf" | "pptx" | "epub")` creates an owned editable native document with copy and atomic path saving. EPUB creation appends semantic content to reflowable EPUB 3 chapters. Extracted Python values remain independent snapshots. PDF `Document.edit()` uses a conservative preservation profile. See [Authoring](authoring.md) for the supported methods.

Language and supported typography inherit through content elements. Consecutive TTML intervals with identical words and different styles stay distinct. A cue's legacy equality and hash still compare its original fields. Compare `runs` and `background_color` for style equality. The synchronized video iterator returns the same typed cues. It leaves caption drawing to the caller. [TTML styling](https://www.w3.org/TR/ttml2/#styling)

TTML captions expose `EpubTtmlRegion` on `EpubTextCue.ttml_region_layout`. Named regions come from `head/layout` and can be selected on a paragraph or inherited from its body or division. A division or paragraph can also define its own child `region`. Its geometry and styles follow the parent’s time interval. An explicit `region` attribute on the parent takes precedence over its child region. An inline region without an authored ID exposes its geometry with no ID, and can be inherited by descendant paragraphs. With no named or associated inline region, the reader exposes the anonymous full-viewport region. A cue with no associated region in a track with named regions keeps its text and has no typed geometry. Region definitions support rectangular origin and extent in percent, cells, or pixels with a pixel root extent. Keyword and percentage positions can align the rectangle in its root viewport. Referenced styles, nested region styles, and inline region declarations apply in that order. The region carries block alignment, writing mode, physical padding, overflow, background and stacking hints. `viewport_bounds(width, height)` and `content_bounds(width, height)` use the supplied display viewport for the outer and padded content rectangles. [TTML region layout](https://www.w3.org/TR/ttml2/#layout-semantics), [TTML style resolution](https://www.w3.org/TR/ttml2/#style-resolution)

TTML run styles inherit a region’s foreground color, font weight and style, and three independent text decoration flags. Chained references, nested region styles and direct declarations are resolved before inheritance. Document `initial` declarations supply defaults for the supported run properties. Content declarations and active content `set` changes take precedence, including explicit resets to normal weight or disabled decoration. A paragraph’s region selection changes its defaults without replacing styles authored on ancestor content. Region background stays on the region layout. [TTML region style inheritance](https://www.w3.org/TR/ttml2/#semantics-style-inheritance-region), [TTML inline regions](https://www.w3.org/TR/ttml2/#semantics-inline-regions)

A named TTML region's `begin`, `end`, and `dur` limit its cues on the original media clock. Caption and video seeks keep the same region and style with clipped times. Staged TTML resources validate their region definitions, style and region references, geometry, and activation timing. Conditional regions, additional typography such as font family, size and line-layout properties, and implicit viewport fitting remain open. The caption API reports backgrounds with visible cues. Painting empty regions or laying out and drawing subtitles remains under caller control.

TTML supports one-shot inline `<set>` changes for foreground color, font weight and style, and text decoration. Place the set inside parallel body, division, paragraph, or span content. Its begin, end and duration use the enclosing element's media-time clock. The style reverts when the set ends and respects the target's time bounds. Different properties can change together. Cue intervals split when the effective style changes, including during synchronized video playback, and adjacent equal styled intervals merge. Repeats, frozen fills, out-of-line animation, continuous animation, and overlapping sets on the same property of one target return explicit unsupported errors. [TTML animation](https://www.w3.org/TR/ttml2/#animation)

Named regions in `head/layout` and child regions of TTML divisions or paragraphs can use direct one-shot `set` children to change origin, extent, position, padding and background color. Parallel sets use the region's start. An inline region starts with its owning block, including when that block follows another item in a sequence. Descendant paragraphs inherit that same clock until they select their own region. Sequential sets begin relative to the preceding set's end. They default to zero duration, and an explicit end can supply the duration when no repeat count is given. The region returns to its previous geometry and background when an active set ends. Distinct properties can animate at the same time. Bounds are recalculated for each state, including position relative to the new extent and padding relative to the region size. A caption splits at effective layout changes while retaining its ID, text and styled runs. Seeking uses the same source-clock state, and synchronized video reuses the decoded picture across caption transitions. Staged edits and playback both validate the sets and allow up to 32 sets per region and 4,096 per-region animation boundaries in total. Region changes leave the containing content sequence timing intact. The parser also limits the cumulative geometry declaration bytes it evaluates. Unlisted region properties, overlapping sets on the same region property, and conditional ownership or independent timing attributes on an animated inline region return explicit unsupported errors. [TTML region animation](https://www.w3.org/TR/ttml2/#animation-vocabulary-set), [TTML timing](https://www.w3.org/TR/ttml2/#timing)

A TTML paragraph without its own or an inherited region can contain contiguous span groups that each select a different named region. Each group produces its own cues and keeps the paragraph ID. It has separate geometry, styling, activation and presentation intervals. Default XML indentation can separate independent groups. The reader keeps collapsed spacing, explicit line breaks and preserved whitespace inside each group. Standalone cues are ordered by time. Video retains the groups’ authored order when they overlap, including across simultaneous changes and seeks. Mixed paragraphs with conflicting ancestor assignments, unassigned text or preserved whitespace, or a return to an earlier region raise an explicit error during playback. [TTML region association](https://www.w3.org/TR/ttml2/#associate-region), [W3C discussion of descendant region ambiguity](https://github.com/w3c/ttml1/issues/194)

TTML timed content can use boolean `condition` expressions with `true`, `false`, parentheses, `!`, `==`, `!=`, `&&`, `||` and `parameter('forced')`. The default binds `forced` to false. Pass `ttml_forced=True` to `epub_embedded_text` or to `epub_embedded_video` with a selected text track to activate authored TTML forced-subtitle conditions. Staged edits use ordinary playback validation. Conditions that become active in forced mode are validated during forced playback. Timed body, division, paragraph, span and line-break elements can use the supported expressions. Excluded content with an authored end or duration keeps its interval in sequential timing and omits its text and styles. Supported one-shot `set` children of parallel text owners and named or inline regions also accept `condition`. A false set participates in the owner's timing, including a region's sequential cursor, without changing styles or introducing caption boundaries. An active set restores the previous style or region value when it ends. Staged resources and playback validate expressions and report unsupported context functions, unavailable parameters, and excluded content with an implicit duration. Mixed-region paragraphs group the visible spans in authored order, including when conditions leave gaps in a sequential paragraph. Visibility changes can reveal conflicting region order, which raises an explicit error in that playback mode. Direct content sets under a sequential time container, conditional layout elements, and conditional style definitions remain open. [TTML conditions](https://www.w3.org/TR/ttml2/#content-attribute-condition), [TTML bound parameters](https://www.w3.org/TR/ttml2/#content-value-bound-parameter)

Local video URLs can select a spatial rectangle with `#xywh=10,20,80,60`, `#xywh=pixel:10,20,80,60`, or `#xywh=percent:25,25,50,50`. Combine one spatial and one temporal range with `&amp;` in XHTML, in either order. `EpubMediaSource.fragment_xywh` exposes the authored `(unit, x, y, width, height)` tuple or `None`. Pixel units use the displayed picture after applying the container crop and pixel aspect ratio. The returned RGB raster covers the rectangle and retains the original pixel aspect ratio. Integer percentages round the top-left down and the size up and must fit within 100 percent. A pixel rectangle extending beyond a picture edge is clipped at that edge. An origin outside the picture, an invalid rectangle or repeated dimensions return explicit errors. The spatial selection preserves soundtrack and caption timing. [Media Fragments URI spatial dimension](https://www.w3.org/TR/media-frags/#naming-space)

Local WebM and Ogg URLs can select named tracks. For example, `#track=Wide%20Angle&amp;track=Commentary&amp;t=0.5,2.25` selects one picture track and one soundtrack in XHTML. Repeat `track` for each name and use percent encoding for spaces and separators. Name matching is exact and case sensitive. WebM uses the TrackEntry Name and Ogg uses the Skeleton Name associated with each stream serial. `EpubMediaSource.fragment_tracks` exposes the distinct decoded names in authored order. A named fragment selects at most one video and one audio track. Calls for a media type omitted from the fragment return an explicit unsupported error. Absent and ambiguous names fail explicitly, and an ordinal selector cannot be combined with named selection. Local caption files remain selected by `text_track`. [W3C track fragment syntax](https://www.w3.org/2008/WebVideo/Fragments/WD-media-fragments-spec/), [Matroska track names](https://www.rfc-editor.org/rfc/rfc9559.html#section-5.1.4.1.18), [Ogg Skeleton Name](https://wiki.xiph.org/SkeletonHeaders#Name)

For separate synchronized audio playback from an Ogg chain with multiple Theora tracks, use a named video and audio fragment. Video ordinal playback follows the selected picture stream and a unique default soundtrack. In a chained Ogg resource, each segment must declare the selected names with consistent media types. A named soundtrack can switch between Opus and Vorbis when every link has the same 48 kHz speaker layout. Named Ogg supports Skeleton 3.0 and 4.0 with zero time origins and zero selected track base granules. On a video element with both tracks selected, the end of the longer selected track determines the next segment's start. An audio-only named selection follows the lengths of its soundtrack links. Crop selection, seeking, and captions use the same playback clock. Mismatched sample rates or speaker layouts return explicit errors. [Ogg Skeleton](https://xiph.org/ogg/doc/skeleton.html), [Theora multiplexed stream mapping](https://xiph.org/theora/doc/Theora.pdf)

A mixed Opus and Vorbis resource can also play without a track fragment when each physical link has one supported soundtrack, no competing recognized audio, and the same 48 kHz speaker layout. Authored Skeleton soundtrack names must agree when present. Skeleton time origins and associated track bases must be zero in this profile, and a mixed chain is limited to 256 links. Embedded playback and SMIL narration retain the same PCM, and video uses the selected picture and soundtrack durations for the caption clock. Uniform chains and explicit codec or track selections retain their existing behavior. [Ogg chaining](https://xiph.org/ogg/doc/oggstream.html)


A local WebM source can resolve an ID such as `#id=chapter-2` to a temporal fragment. Match an exact Matroska ChapterStringUID or a decimal ChapterUID. `EpubMediaSource.fragment_id` exposes the decoded ID. The interval starts at the chapter's authored time and ends at its explicit end, the next later sibling marker, the enclosing chapter boundary, or the end of the source. The reader rounds nanosecond bounds up to its microsecond clock and intersects the chapter with the requested interval. Named tracks and a spatial crop can be combined with an ID. The same interval bounds audio, video, and synchronized captions.

Duplicate or missing IDs, a URL combining `id` with `t`, and malformed chapter timings return explicit errors. This profile supports simple local chapters, including nested chapters. An ID that refers to ordered, linked, restricted, or command-bearing chapters returns an unsupported error. Chapters stored after media clusters require a valid SeekHead. Remote sources remain inert. [W3C ID fragment syntax](https://www.w3.org/2008/WebVideo/Fragments/WD-media-fragments-spec/), [Matroska Chapters](https://www.rfc-editor.org/rfc/rfc9559.html#section-20)

A local MP4 or M4A source can resolve `id` to an exact, case-sensitive QuickTime chapter title. An enabled track must reference the local chapter text track. Titles use UTF-8 or UTF-16 with a byte order mark. The chapter sample interval is mapped through the track's continuous edit, including an optional initial gap, to the movie clock. A spatial `xywh` fragment can accompany the ID on video. Both bounds round up to microseconds and clip the existing picture, AAC soundtrack and synchronized captions. The profile allows 4,096 markers and 1,024 UTF-8 bytes per title. Duplicate targets and titles, missing titles, malformed text and timestamps, and external data references fail explicitly. Discontinuous chapter-track edits and ID fragments in other containers remain open. [Apple MP4 chapter tracks](https://developer.apple.com/library/archive/technotes/tn2174/), [W3C ID fragment syntax](https://www.w3.org/2008/WebVideo/Fragments/WD-media-fragments-spec/)

MP4 and M4A also support a standalone Nero `moov/udta/chpl` table. The reader accepts compact version 0 and version 1 up to 4,096 markers, requires strictly increasing 100-nanosecond starts within the movie and matches the exact UTF-8 title. Each chapter ends at the next marker or the movie end, with both bounds rounded up to microseconds. An ID can match any chapter index in the file. Indexes that provide the same title must agree on its effective playback interval. Malformed chapter metadata returns an explicit error during ID selection. Plain time fragments still use the ordinary playback path. [FFmpeg Nero chapter writer](https://github.com/FFmpeg/FFmpeg/blob/eb36dce742c32140a1ea1de83013b88a681595ed/libavformat/movenc.c#L4955), [MP4v2 Nero chapter table](https://android.googlesource.com/platform/external/mp4v2/+/185cebee41a061bb66761249b3c82a10bcc2232d/src/atom_chpl.cpp)

The legacy Adobe F4V version 0 table sits directly under `moov` as `moov/chpl`. Its up to 255 markers use the movie header’s timescale. The reader matches exact UTF-8 titles and rounds both chapter bounds up to microseconds using the source movie clock. The interval ends at the next marker or the movie end. It synchronizes supported H.264 pictures, AAC-LC audio and XHTML captions with ID fragments and video crops. The same path accepts packaged `video/x-f4v` resources. QuickTime track, Nero table and F4V table titles can coexist under the same agreement rule. [Adobe Video File Format Specification, version 10](https://rtmp.veriskope.com/pdf/video_file_format_spec_v10.pdf)

Pass `text_track` to `epub_embedded_video` to attach the selected track to each frame's `text_cues`. A caption boundary inside a decoded frame divides its presentation interval while reusing the same RGB bytes. Clips reconstruct overlapping active cues at the seek point. A video interval can carry up to 128 simultaneous cues. [Media Fragments URI](https://www.w3.org/TR/media-frags/#npttimedef)

EPUB 3 media overlays are exposed under `Document.metadata["media_overlays"]`, keyed by manifest ID. They retain nested SMIL sequences, structural roles, target element IDs, and local audio paths. `Document.epub_media_cues(page)` gives a chapter's ordered cues with audio bounds in integer microseconds. Narration uses the end of the source audio when `clipEnd` is absent or extends past the media. The cue metadata retains the authored clip bounds. A start outside the playable audio returns an explicit error. `Document.epub_narration(page)` decodes local MPEG Layer III, AAC-LC in MP4, Ogg Opus in mapping families 0 and 1, Ogg and WebM Vorbis with one to eight channels, and PCM WAVE to signed 16-bit PCM WAVE and extracts readable text for text-only cues. `Document.play_epub_narration(page, ...)` sequences the caller's blocking audio, speech and active-target callbacks. Both methods accept `start_cue`, a zero-based chapter cue index. To start from a navigation destination, pass its decoded fragment ID as `start_fragment` and leave `start_cue` at zero. For example, pass `start_fragment="café-section"` for a link ending in `#caf%C3%A9-section`. A matching SMIL sequence starts at its first cue on that page. Both start options are applied before `skip_roles`. When the ID has no explicit SMIL target, an XHTML body descendant can start at the nearest enclosing text cue, including a whole-chapter cue. A fragment with no associated cue on the selected page raises `IndexError`. Pass `audio_tracks={"EPUB/audio/voices.webm": 1}` to select the second WebM audio track for that resource. The `opus_tracks` mapping remains available for Ogg Opus. Select each resource through one mapping.

A playback caller can return an active `table`, `list`, `figure` or `aside` role from `escape_role(cue)` after an audio chunk or text cue. Playback leaves the innermost SMIL element with that role, suppresses the remainder of that structure, and resumes at the next cue on the selected page. Returning `None` continues current playback. [EPUB reading system escapability](https://www.w3.org/TR/epub-rs-33/#sec-escapability)

SMIL clock values and authored package durations use checked decimal conversion to the nearest microsecond, with half-microseconds rounded up and surrounding whitespace ignored. Both audio endpoints then round up to the next sample timestamp when needed and exclude the end sample. Source audio is bounded to 32 MiB and each buffered clip to 16 MiB of PCM. Pass `chunk_frames` from 1 to 262,144 to process a long cue in smaller WAVE clips. `epub_narration` yields the same target information for each of its audio chunks, and `play_epub_narration` holds the active target across those chunks. [EPUB media overlay audio playback](https://www.w3.org/TR/epub-rs-33/#sec-rsconf-rendering-audio)

MP4 playback supports rate-1 media edits with an optional leading empty interval. Consecutive edits describe one media interval when each authored boundary is exactly contiguous in the movie and media timescales. Playback keeps the same picture, audio and chapter boundaries as an equivalent single edit. A track can preserve up to eight source spans after joining contiguous edits. At each boundary, playback can jump forward, replay an earlier span in forward order, or leave an authored gap on the movie clock. AVC restarts from its preceding sync sample, AAC restarts with overlap preroll at sample-aligned edit bounds, and chapter titles are mapped across the selected source intervals. Each local edit list is limited to 64 entries. Picture occurrences and cumulative decoder access units have separate work limits. A finite movie duration beyond the edited track supplies an implicit trailing empty interval. Empty intervals yield no AVC pictures and supply silence to AAC on the original movie clock. Chapter IDs and captions keep their movie-time bounds, including clips that cross either gap. A continuous chapter track can name an interval inside a picture or soundtrack gap. A title whose projections touch at the edit boundary retains one continuous interval. A title that maps to disjoint intervals in its own chapter track returns an explicit error. An explicit final empty edit and dwell edits remain unsupported. MP3 applies encoder delay and end padding on validated Xing/Info tags from LAME or FFmpeg, and files without recognized timing metadata use the MPEG frame timeline. Ogg Opus accepts single and sequentially chained mono, stereo and surround streams. Each link applies its own pre-skip and output gain and ends at its final granule. Cues use one continuous timeline. Surround output uses extensible WAVE with each speaker identified by the channel mask. A chain uses the combined speaker positions of its non-mono links, leaving absent speakers silent. Mono uses the center speaker when the output has one and otherwise plays through both front channels. Multiplexed `audio/ogg`, `application/ogg` and `video/ogg` resources can supply narration. Both narration methods accept `opus_tracks`, a mapping from decoded archive paths to zero-based Opus track indices in identification page order. For example, `opus_tracks={"EPUB/audio/voices.ogg": 1}` selects the second Opus track in every segment of that resource. A missing selection for concurrent tracks or an index absent from a segment returns an explicit error. The reader validates Ogg transport for every stream, including unselected tracks. To package Opus for an authored overlay, use the EPUB core type `audio/ogg; codecs=opus` and provide an explicit clip end. Fragmented MP4, built-in speech synthesis, and an audio-device implementation remain open. [EPUB 3.3 media overlay specification](https://www.w3.org/TR/epub-33/#sec-media-overlays), [Ogg Opus specification](https://www.rfc-editor.org/rfc/rfc7845.html)

Ogg and WebM Vorbis use the standard encoded channel order for one to eight channels. Surround output uses extensible WAVE with its speaker mask and samples in WAVE order. Applications define the speaker order for Vorbis streams with more than eight channels. Playback of those layouts returns an explicit error. Ogg Vorbis uses granule positions for leading silence or overlap trim and to trim the presentation tail. Chained Vorbis audio preserves a single sample rate and channel count. Both Ogg audio codecs validate the surrounding multiplexed transport. Automatic selection prefers Opus when both codecs are present. [Vorbis I specification](https://xiph.org/vorbis/doc/Vorbis_I_spec.html)

Pass ordered `EpubOverlayCue` and `EpubOverlaySequence` values to `edit_epub_structure(overlays=...)` to attach authored narration to a chapter. A sequence can contain cues and other sequences, target a fragment or the whole chapter, and set `epub_type` roles inherited by its cues. The editor accepts up to 32 levels of sequence nesting and 10,000 timing entries per edit. Supply `None` to detach a chapter's association. Replacing or detaching a chapter in a shared SMIL resource preserves the other chapters' cues, IDs and roles. The editor removes empty sequences, retargets surviving containers when needed, and updates the SMIL and publication duration metadata. Replacing an associated SMIL file through `resources` also updates both duration declarations against the staged chapter and audio data. A duration refinement can point to its manifest ID through an escaped fragment or the relative package URL. Removing a detached overlay removes its duration declaration, provided that a retained refinement does not target it. Open-ended clips can use the presentation duration of supported local audio. Replacing that audio through `resources` refreshes the associated overlay and publication durations even when the SMIL is unchanged. The reader parses bounded UTF-8 XML and recognizes plain HTML and selected legacy XHTML, NCX and SVG doctype declarations. Parsing is offline. Custom DTDs and script execution are unsupported. Supported XHTML and static SVG CSS declarations can use unregistered custom properties and var() fallbacks. Custom properties inherit their computed values and keep case-sensitive names. Static SVG supports `use` with literal fragment IDs for graphics and symbols in the same SVG subtree. Both `href` and `xlink:href` are accepted, with `href` taking precedence. Each SVG use instance inherits computed custom properties from its host, including through nested references and symbols. Reused text inherits the supported font family, weight, width, style, optical sizing and variation settings from each instance. Local paint servers inside a reused subtree keep the instance's colors. Use stylesheet or inline CSS declarations for variable substitution. Reopened fixed-layout PDF preserves measured SVG text links and links around rendered instances.
