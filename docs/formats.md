# Formats, rendering, and conversion

This development guide describes the 0.3.1 baseline and explicitly marked unreleased work. EPUB support is unreleased. See the [validation record](../.kiro/specs/rust-document-engine/validation.md) for tested artifacts.

The [operation evidence matrix](support-matrix.md) separates reading, creation, authored/imported editing, preservation, rendering and export for explicitly audited profiles. It links all roadmap criteria and records historical artifact evidence without claiming complete parity.

## PDF

PDF support is backed by pinned PdfCraft 0.9.0 crates.

### Extracted data

- Pages in source order.
- Reading-order text represented as line-oriented paragraph blocks.
- Text and image bounding boxes in displayed page coordinates.
- Page width, height, rotation, and label.
- Document title, author, subject, keywords, creator, producer, PDF version, encryption state, and tagged state when available.
- URI link destinations and rectangles.
- Non-form images that PdfCraft can export as PNG or JPEG, including width and height.
- Conservative table candidates derived from public positioned reading blocks.

### PDF table detection

PdfCraft 0.9.0 does not expose its internal table detector as a public Rust API. `pydoccraft` therefore uses a small geometry normalizer. It reports a table only when it finds at least two rows and two columns with consistent row alignment, equal column counts, and stable column positions. Text blocks represented by the table are removed from normal paragraph output to avoid duplication.

This deliberately favors false negatives over fabricated tables. Borderless, irregular, spanning, rotated, or visually complex tables may remain plain text.

### PDF links

PdfCraft exposes link destinations, rectangles and text geometry. The adapter recovers unambiguous labels with normalized Unicode character offsets, including repeated labels and contiguous multiline labels, and Markdown attaches those targets inline. Accepted multiline annotations coalesce their consecutive paragraph blocks while retaining native spaces/newlines and unchanged plain text. Neighboring links retain correct offsets. Links inside inferred PDF table cells retain empty labels to avoid duplicating cell text. Overlapping, noncontiguous or ambiguous geometry-only links also retain empty labels and appear in the final **Links** section; the adapter does not infer a reading order across columns or guess omitted glyphs.

### PDF images

Images nested in grouped Form XObjects or encoded in formats the upstream image exporter cannot materialize may be omitted. Extraction is not an inventory of every PDF stream. Rendering remains available even when individual image extraction is unavailable.

### Scanned PDFs

A scan-only page can be rendered but produces no text unless the PDF already contains a text layer. `pydoccraft` contains no OCR engine or model.

## DOCX

DOCX support is backed by pinned WordCraft 0.8.0 crates.

### Extracted data

- Ordered body paragraphs and tables.
- Heading levels resolved through style inheritance and clamped to Markdown levels 1–6.
- Style ID, style name, and outline metadata.
- Resolved numbering definitions and unambiguous native layout labels, separate from paragraph text. See [numbering extraction](numbering-extraction.md).
- Exact hyperlink labels and character offsets.
- Referenced inline and grouped images with bytes, display dimensions, and alt text.
- Semantic tables, including content from nested table cells.
- Anchored comments and replies with author, initials, date, resolved state, and parent identifiers.
- Explicit manual page breaks and inherited `page_break_before` behavior.
- Core document metadata where available, plus bounded supported scalar custom properties.
- Table title/description in `Table.metadata`, separate from visible cell text.

### DOCX properties and field values

`document.metadata["custom"]` maps original property names to strings, booleans, signed 64-bit integers or finite floats for the supported native `lpwstr`, `bool`, `i8` and `r8` kinds. Parsing follows the same strict scalar profile as authored properties; other numeric aliases and structured/raw variants are not coerced. Unsupported kinds, invalid scalar values and ambiguous ASCII-case-insensitive names are omitted with bounded extraction diagnostics. All entries in an ambiguous name group are omitted.

The parsed inventory is capped at 1,024 properties, 64 KiB per value and 256 KiB aggregate raw metadata, including names/kinds. This is a native-model inventory, not a promise of complete source XML preservation: the upstream reader can drop malformed custom parts, omit entries and cap source property traversal before projection. Table alternative text is likewise capped by the upstream reader at 10,000 Unicode characters. Extracted `title`/`description` preserve native absent versus empty values; neither becomes a visible cell caption or a PDF accessibility tag.

Source field text uses stored cached values. Newly authored decimal page/count fields have an empty dirty cache, while PNG/PDF output is evaluated by native layout. General field refresh and convergence remain unsupported.

### DOCX pagination

WordCraft computes layout pages. A paragraph that spans multiple computed pages but contains no explicit page break is emitted once on the first page it occupies because the upstream public model does not expose exact normalized text slices for each laid-out page.

Tables are associated with their first page rather than split into separate normalized table fragments. `Table.rows` retains newline/tab cell text for compatibility; `Table.cells` additionally preserves ordered paragraph/table blocks and horizontal/vertical merge information. Markdown uses HTML for nested, merged, or rich tables. This extraction structure does not provide an editable document model.

Unreferenced files in `word/media/` are not returned.

## PPTX

PPTX support is backed by pinned DeckCraft 0.8.0 crates.

### Extracted data

- One normalized page per slide in presentation order.
- Recursive traversal of grouped shapes with transformed geometry.
- Paragraph and soft-line-break boundaries.
- Run-level URL and resolved internal-slide hyperlinks with exact labels and offsets, including table cells.
- Shape/group URL and resolved internal-slide links.
- Semantic tables and merge metadata.
- Referenced picture bytes, MIME type, alt text, intrinsic dimensions when detectable, and slide placement.
- Speaker notes.
- Comments and nested replies.
- Slide dimensions, name, and hidden state.

Resolved native slide targets use `#page=N` and zero-based `target_page` metadata, including self-links and hidden slides in presentation order. Context-dependent next/previous/first/last/last-viewed actions, end-show, media, custom-show and program actions remain explicit omission diagnostics; they are not treated as fixed page targets. Notes retain their existing text-only link behavior. Unknown action strings and unresolved source relationships can be discarded by the pinned reader before the adapter sees them, so their absence cannot be diagnosed completely without upstream preservation reports.

## Rendering

An open document reuses its native PDF parser or Office model for repeated rendering. DOCX also reuses the completed pagination layout. The public methods and PNG-byte return type are unchanged. Use a context manager or `close()` to release retained models/layouts and private source/password references; already extracted values remain usable. Retention can increase steady-state memory. Native global/thread-local caches and allocator retention are not released by this contract, and calls do not promise parallel rasterization. See [Office measurements and reproduction](office-performance.md).

```python
png = document.render_page(0, dpi=144)
png = document[0].get_pixmap(dpi=144)
detail = document.render_page(0, dpi=300, clip=(36, 36, 144, 72))
```

Both methods return encoded PNG bytes.

- PDF rendering uses PdfCraft pixels and rejects oversized output.
- DOCX rendering uses WordCraft layout and its page renderer.
- PPTX rendering uses DeckCraft slide rendering.
- EPUB renders a fixed chapter in its declared viewport and a reflowable chapter on a scrolling surface 612 points wide.
- `dpi / 72` is used as the native scale.
- DPI must be finite and between 1 and 1200.
- Out-of-range pages are rejected in Python before native dispatch.

DPI controls raster scale and embedded PNG resolution metadata for all three formats. Pixel dimensions follow each engine's rounding; physical resolution uses integer pixels per meter. The multi-DPI corpus checks dimensions, metadata, decoded PNG data and visible content. PDF rotation, crop offsets and UserUnit are covered by the geometry corpus; broader cross-format fidelity remains in the [rendering validation TODOs](../TODO.md#p0--rendering-at-a-requested-dpi).

Each output is bounded to 64 million RGBA pixels in addition to upstream maximum-side limits. DOCX/PPTX dimensions are checked before rasterization; PDF uses upstream oversize rejection. DeckCraft can internally replace a rendering panic with a blank slide. The adapter checks its process-wide panic counter and reports a detected panic as an error for rendering and PDF export. A panic on another thread can cause a spurious error; see the [upstream contract](../AGENTS.md).

Optional `clip=(x, y, width, height)` is available on both methods, including editable document/page/slide wrappers. Coordinates use displayed-page points with a top-left origin; PDF rotation, CropBox and UserUnit are already applied. The rectangle is intersected with the displayed page and snapped outward to its native pixel grid at the requested DPI. Empty intersections, nonfinite values and nonpositive dimensions raise `ValueError`. At page edges, each backend retains its full-page rounding convention; fractional boundaries can add an edge pixel.

Clips use native PdfCraft tiles, WordCraft region rendering and DeckCraft offsets, without allocating a full-page raster first. PDF clips are limited to 4,096 pixels per side and exactly representable tile offsets; Office clips retain the 16,000-pixel side and 64-million-pixel limits. Valid but excessive requests raise the existing resource-limit exception. The returned PNG keeps requested DPI metadata and native page/slide background. Arbitrary background replacement and faithful transparent rendering remain unavailable; clipping does not emulate them by recoloring white pixels. Native parsing/layout still processes the document, so clipping is not selective extraction or a complete memory bound.

Region and full-page rasterization can differ slightly at antialiased edges after native transform translation. The measured PDF text fixture differed by at most two pixels and the fractional-DPI PPTX rectangle by 124 pixels on one edge row, each by at most 1/255 in RGB with identical alpha. Those fixtures use explicit tolerances; full-page/boundary and rotated-PDF shape comparisons remain exact. Fractional PPTX slide edges can retain native partial alpha. These measurements do not establish universal pixel identity or fidelity tolerances for arbitrary effects.

The returned value is not a PyMuPDF `Pixmap`; write it directly or load it with an image library:

```python
from pathlib import Path

Path("page.png").write_bytes(document[0].get_pixmap())
```

## Conversion matrix

| Source | Target | Implementation | Notes |
|---|---|---|---|
| PDF | DOCX | PdfCraft extraction values → `pdfcraft-export` DOCX writer | Positioned text styling and exportable images; not semantic PDF-table conversion |
| DOCX | PDF | WordCraft layout and PDF export | Supports Unicode and tested explicit empty pages |
| PPTX | PDF | DeckCraft PDF export | Slides become PDF pages with a searchable text layer where supported |
| EPUB | DOCX | Semantic EPUB blocks → WordCraft DOCX writer | Reflowable content, with each chapter beginning on a new page |
| EPUB | PDF | Semantic EPUB blocks → WordCraft PDF export | Same content profile as EPUB to DOCX, laid out as printable pages |

DeckCraft PDF export corrupts searchable text for PPTX paragraphs containing explicit breaks; native PDF export of those documents is unsupported until the upstream defect is fixed. A visually correct slide is not evidence that its PDF text layer is correct.

Every other pair—including identity conversions, PDF→PPTX, DOCX→PPTX, and PPTX→DOCX—is rejected explicitly.

```python
import doc_ex

word_bytes = doc_ex.convert("source.pdf", "docx")
pdf_bytes = doc_ex.convert("source.docx", "pdf")
slide_pdf = doc_ex.convert("slides.pptx", "pdf")
```

Conversion is not pixel-perfect. Font substitution, unsupported PDF constructs, Office layout differences, grouped graphics, complex tables, and upstream exporter limitations can change appearance. Always reopen and validate converted output for the intended workflow.

## Document creation

`doc_ex.new("docx" | "pdf" | "pptx" | "epub")` creates an owned editable native document with copy and atomic path saving. EPUB creation appends semantic content to reflowable EPUB 3 chapters. Extracted Python values remain independent snapshots. PDF `Document.edit()` uses a conservative preservation profile. See [Authoring](authoring.md) for the supported methods.

## EPUB (unreleased)

Each spine entry maps to one compatibility `Page` in reading order, including repeated and non-linear entries. The page represents a chapter boundary. Extraction preserves semantic text, inline character offsets, nested tables, referenced images, and MathML markup with readable text. Raster image bytes are returned as stored. Static SVG passes a restrictive validation profile and remains inert data.

`Document.metadata["dublin_core"]` contains repeated Dublin Core values keyed by field name. `package_metadata` contains OPF meta records and their refinement targets. `navigation` contains nested navigation groups from an EPUB 3 navigation document or EPUB 2 NCX. `manifest` describes packaged resources. Use `Document.read_epub_resource(path, offset=0, length=None)` with a decoded, relative archive path to retrieve a resource or byte range, limited to 16 MiB per call.

EPUB 3 XHTML chapter insertion and replacement declare embedded MathML and inline SVG in the OPF. Removing the markup through a replacement removes the corresponding declaration. Other manifest properties are preserved. A spine edit also updates the compatibility NCX when the EPUB 3 spine references one. Standalone SVG chapters use `image/svg+xml` and can be inserted as fixed-layout chapters or replaced at their existing spine positions. [EPUB resource properties](https://www.w3.org/TR/epub-33/#sec-item-resource-properties)

PNG preview applies supported author CSS to XHTML. Stylesheets and imports resolve relative to their archive members. The cascade covers inline declarations, specificity, source order, `!important`, supported type, class, ID and attribute selectors, and basic media queries. Rendered properties include typography, spacing, solid borders, backgrounds, block flow, flex and simple grid, and positioned boxes. Fixed-layout EPUB honors the package default and spine overrides. XHTML uses its numeric viewport meta tag and static SVG uses its viewBox. Tall styled reflowable chapters support full previews at a DPI that fits the raster limits and clipped previews within the chapter. Clipped previews bound packaged-font outline painting to the requested raster region. In page metadata, `viewport` is measured in points, with one CSS pixel equal to 0.75 points. [EPUB 3.3 layout specification](https://www.w3.org/TR/epub-33/#sec-fixed-layouts)

Horizontal XHTML previews and fixed-layout PDF support logical inline and block sizes, min/max sizes, margins, padding, insets, overflow axes and solid borders. Inline starts and ends follow the element's left-to-right or right-to-left direction. Physical and logical declarations compete under the same importance, selector specificity and source order. Explicit inheritance takes the matching parent side, even if the child changes direction. Vertical logical layout and automatic direction for sides that depend on the inline direction return explicit errors. [CSS logical properties](https://www.w3.org/TR/css-logical-1/#box)

Archive-local static XHTML in an `iframe` or an `object` typed as `application/xhtml+xml` renders in its own viewport. Child styles and media queries use that viewport, and transparent areas show the host page. Nested content clips to each frame. Fixed-layout PDF can retain visible child text and links to selected spine pages or supported external URLs. Semantic DOCX and PDF render static frames as images. Scripts, remote frame sources, `srcdoc`, fragment scrolling, and percentage sizing for a frame inside a text run are unsupported. [HTML embedded content](https://html.spec.whatwg.org/multipage/iframe-embed-object.html)

`Document.render_epub_spread(page, dpi=144, orientation="landscape", clip=None)` renders the spread containing a spine entry. It honors EPUB progression direction, page placement, and package and spine spread rules. The `auto` policy pairs pages in landscape. Facing viewports keep their original sizes and top alignment. A blank facing slot has the same size as the present page. A clip is relative to the combined spread raster and uses points. `render_page` renders an individual spine entry. [EPUB Reading Systems fixed layout](https://www.w3.org/TR/epub-rs-33/#sec-fxl-props)

The renderer loads local `@font-face` sources relative to their stylesheet, including imports. It supports TrueType, OpenType, WOFF and WOFF2. Reflowable and fixed-layout XHTML match authored font weight and width ranges, including fractional values. Oblique styles support signed angles and font-face ranges. Width is matched before style, followed by weight. The selected oblique angle maps to the OpenType slant axis before the face's variation defaults and element settings. Synthetic oblique applies the requested signed fractional shear to the selected upright face's glyph outlines and preserves the shaped advances. Shears outside the paint geometry budget return an explicit error. Static SVG also matches fractional weight and width ranges and signed oblique angles for packaged font faces. The font collection is scoped to each rendered chapter. XHTML and static SVG previews support CSS `font-variation-settings` and `font-optical-sizing` for packaged variable fonts. XHTML and static SVG apply descriptor defaults to the selected face of each supported run, including fallback faces. Automatic optical sizing can override the face default. An element's inherited or specified axis settings take precedence and the last value wins for repeated axis tags. [CSS font variation settings](https://www.w3.org/TR/css-fonts-4/#font-variation-settings-def) XHTML and static SVG previews apply `@font-face` Unicode ranges to packaged glyph coverage. When equal-style ranges overlap, the later matching declaration takes precedence. Missing glyphs use the remaining named or generic families in the inherited `font-family` list before other available fallback faces. Quoted font names retain their literal meaning, including names that match generic keywords. [CSS font-family matching](https://www.w3.org/TR/css-fonts-4/#font-family-prop) It supports the standard IDPF font obfuscation declared in `META-INF/encryption.xml`. Resource reads return the packaged bytes. To replace an obfuscated font with `edit_epub_structure`, pass plain font bytes in an `EpubResource` with the existing media type. The editor applies the package's existing obfuscation key. Removing a font requires that no retained chapter or resource references it. The editor removes its declaration and omits the file after the last declaration is removed. [EPUB 3.3 font obfuscation](https://www.w3.org/TR/epub-33/#sec-font-obfuscation)

Static SVG supports embedded CSS and archive-local CSS linked by an `xml-stylesheet` prolog instruction. Its supported CSS covers paint and typography, including archive-local fonts and same-document paint references. Static SVG accepts the standard image, shape, text and color rendering hints. SVG `image` elements can reference packaged PNG or JPEG files by `href` or `xlink:href`. SVG embedded in XHTML or linked through an image renders with transparency. Positioned SVG uses its CSS box and destination resolution. Semantic DOCX and PDF export rasterize static SVG, retaining inline placement and alternative text where the target supports it. When mixed-font shaping requires another pass, SVG text can split into runs at grapheme boundaries. A single variable-font run can retain an explicit text length. Mixed-face text with one horizontal positioned chunk can also retain a positive textLength in user units or pixels with spacingAndGlyphs and solid fills. The fixed-layout PDF uses the adjusted geometry for searchable text and links. Spacing-only adjustment, nested length owners, text paths, per-glyph positioning, reused text with an explicit length, negative spacing, non-solid paint, strokes, effects on measured text, and ambiguous inherited styles can return an explicit unsupported error when fallback requires another shaping pass.

Linear and radial SVG gradients can inherit stops and attributes from local templates. A local SVG filter can chain up to 16 Gaussian blur, drop-shadow, color matrix, flood, offset, composite and merge primitives. Inputs can read SourceGraphic, SourceAlpha or a named result from an earlier primitive. An omitted input uses the preceding result or SourceGraphic at the start of the filter. Color matrices support RGB and alpha transformations, saturation from 0 to 1, hue rotation and luminance-to-alpha. Flood and drop shadow honor CSS flood color and opacity. Offsets are signed. The renderer supports Porter-Duff and arithmetic compositing and up to 16 ordered inputs per merge. Offset subregions at the primitive level return an explicit unsupported error. Filter regions, transformed parameters and native output work share bounded limits. Fixed-layout PDF retains geometry when the final dependency graph preserves source coverage. If output can only remove coverage from one painted source, PDF text and annotations use the surviving native alpha. A single filter layer can move source text, links and destinations through a named offset chain and supported pointwise color operations. Capture uses the render's DPI, transforms, clipping and native pixel rounding. Stacked filter layers and unresolved spatial combinations return an explicit error when the export needs their affected geometry. Visual artwork can still use those effects, and unrelated links and text retain their geometry. One local filter reference per element is supported. Filtering inside SVG patterns, masks and clip paths remains unsupported. [SVG gradient templates](https://www.w3.org/TR/SVG2/pservers.html#LinearGradientElement), [SVG filter primitives](https://www.w3.org/TR/filter-effects-1/)

DOCX and PDF export use WordCraft's semantic reflow profile. They support headings, paragraphs, PNG/JPEG images and rasterized static SVG, basic nested or merged tables, and native equations. Semantic fixed-layout exports and source CSS projection to DOCX and PDF remain open. Conversion rejects internal, overlapping and image-only hyperlinks and features that cannot be projected.

`Document.export_epub_fixed_pdf(dpi=144, pages=None, searchable=False)` produces a raster PDF with one page per selected fixed-layout spine entry, in selection order and at its original viewport size. The image uses the preview’s pixel grid at the export DPI. The PDF viewport can clip a partial outer row or column when reopened. Use `pages` to select fixed-layout entries in a mixed book. The PDF outline preserves the EPUB 3 table of contents or EPUB 2 NCX hierarchy for the selected pages. A repeated chapter resolves to its first occurrence in the export. Bookmarks use the positions of laid-out XHTML boxes, inline text, and SVG objects. Unresolved bookmarks target the top of the chapter. The text layer uses the layout engine’s coordinates and preserves the rendered page pixels. The layer excludes CSS-hidden text and text completely outside the viewport or layout clipping bounds. Search boxes describe laid-out glyph or cluster bounds. Native coverage accounts for nonrectangular SVG clips and for alpha and luminance masks. Search and link boxes remain rectangular, so they can span gaps in the visible coverage. Overlapping ink may be ambiguous. Annotation coverage has its own raster and work limits. [SVG image and inline processing modes](https://www.w3.org/TR/SVG2/conform.html#processing-modes-for-svg-sub-resource-documents)

The Presentation MathML profile preserves inline and display formulas in previews and exports. The original source markup keeps its annotations and indentation. [MathML whitespace rules](https://www.w3.org/TR/MathML3/chapter2.html#fund.collapse)

MathML color, size and variant attributes inherit within supported formulas. Inline, embedded, and archive-local linked or imported CSS can set `color`, `font-size`, `font-weight`, and `font-style` inside formulas. The native equation model carries opaque colors, numeric font lengths, and plain, bold and italic run combinations. `math-style` selects compact or raised placement for movable limits. Fixed-layout previews use the declared viewport for relative CSS lengths. Stacked fractions support custom bar thickness and numerator and denominator alignment in PNG previews and PDF. Thickness accepts lengths, percentages of the native rule, and the legacy thin, medium, and thick keywords. Nonpositive values omit the bar. Custom fraction geometry requires PDF or PNG output. Additional MathML CSS layout properties remain open. [MathML Core math-style](https://www.w3.org/TR/mathml-core/#the-math-style-property)

PNG previews and fixed-layout PDF support row and column spans in MathML tables, including tables inside larger expressions such as fractions, radicals and scripts. Measured MathML grids honor row and column spacing lists and row and cell alignment overrides. Table alignment can use the whole grid or select a row from the top or bottom. Equal rows and columns include the space needed by spanning cells. Supported fixed column widths can be mixed with automatic columns. Widths that require clipping cell content or conflict with equal columns return an explicit error. A definite table width supports percentage columns and the `fit` keyword. Fixed and percentage tracks keep their requested widths, automatic tracks reserve their required widths, and fitted tracks share the remaining space equally after frame spacing and column gaps. A percentage or unitless proportion can size a MathML table up to the full width of a definite containing line. Preview and fixed-layout PDF use the actual XHTML content width after padding and borders. Reflowable PDF and DOCX use their page text width or their native table cell's content width. Nested tables can use the width of a definite MathML cell, including the gaps inside a span. Cells whose widths depend on their contents, and equation operands without an independently assigned width, return an explicit error for relative tables. Conflicts that would clip content return an explicit error. Solid and dashed table rules and frames follow the authored frame spacing and break at spanning cells. PDF preserves vector rules in reflowable export. Standalone ruled tables keep native solid and dashed Word borders, merged cells and editable equations. Word can restart a dash pattern at cell edges, and its border clearance can limit very narrow gaps. Ruled grids embedded in a DOCX equation return an explicit error. Previews apply MathML padding sizes and signed content offsets using supported absolute and content-relative lengths. Vertical math spaces contribute to line height. Standalone tables that fit the export page round-trip as native merged and nested cells with editable equations in DOCX and searchable text in PDF. Reflowable PDF preserves searchable glyphs and vector rules for composed equations, including those inline with text or in XHTML table cells. Composed equations that exceed the page text area return an explicit error. DOCX preserves editable equations with fixed, additive and content-relative padding dimensions and vertical math spaces. DOCX supports signed vertical shifts and nonnegative left offsets, including offsets beyond the padded width. The writer reserves ascent and descent using invisible Office Math phantoms. The native font metrics and DOCX half-point run sizes determine their precision. Spanning tables inside formulas or mixed with paragraph text keep their measured placement and editable expressions in Office Math matrix slots. The placed expressions retain their positions during later edits. Columns closer than WordCraft's native matrix gap use adjacent single-column matrices with their measured advances. Each expression stays editable. pydoccraft extraction recovers the original logical rows from those columns. Negative left offsets still require PDF for export. [MathML padding](https://www.w3.org/TR/MathML3/chapter3.html#presm.mpadded), [MathML 3 table geometry](https://www.w3.org/TR/MathML3/chapter3.html#presm.mtable), [MathML table cell spans](https://www.w3.org/TR/mathml-core/#entry-in-table-or-matrix-mtd)

`Document.epub_embedded_media(page)` lists XHTML audio and video elements in source order. Each entry includes its ID, label, source URLs, archive paths for local media, and any poster or WebVTT or TTML track references. The source flags `playable_audio` and `playable_video` indicate candidates based on the package media type and codec hints. Opening a source checks its actual codec and profile. Previews display the packaged video poster when present and otherwise use the authored fallback markup. Caption files remain available through `read_epub_resource`. Semantic DOCX and PDF conversion reject chapters with embedded media.

`Document.epub_embedded_audio(page, media_index, ...)` yields signed 16-bit PCM WAVE chunks for the caller's playback sink. It tries archive-local audio candidates in authored order and advances on unsupported codecs or profiles. Use `source_index` to select a specific source, `start_us` and `end_us` for the playback interval, `chunk_frames` for buffering, and `opus_track` to select among concurrent Opus streams. Remote URLs and legacy `epub:trigger` elements remain inert. Local media source URLs can select a normal-play-time fragment such as `#t=npt:0.5,2.25`. Audio and video intersect that half-open interval with the requested playback window and keep the original timeline. Source metadata exposes the interval in `fragment_start_us` and `fragment_end_us`. Query-based selection, poster and caption-track fragments, automatic playback, and looping remain open. [HTML media elements](https://html.spec.whatwg.org/multipage/media.html), [EPUB Reading Systems](https://www.w3.org/TR/epub-rs-33/)

`Document.epub_embedded_video(page, media_index, ...)` streams packed RGB8 frames from packaged H.264 MP4, Ogg Theora, or WebM AV1, VP8 and VP9. It tries local video candidates in authored order and advances on unsupported codecs or profiles. Each frame carries its pixel dimensions, pixel aspect ratio, start and duration in microseconds. Use `source_index` to select the source, and `start_us` and `end_us` to request a clip. Pass `video_track` to choose a zero-based video track from a WebM resource. A WebM source with multiple video tracks requires explicit selection. The reader uses container presentation timing, seeks from a preceding keyframe and clips each frame interval to the requested window. For a matching AAC-LC, Opus or Vorbis soundtrack, call `epub_embedded_audio` with the same source and interval. The caller controls the playback clock and output devices. [H.264/AVC](https://www.itu.int/rec/T-REC-H.264), [Theora specification](https://www.theora.org/doc/Theora.pdf)

MP4 playback supports one progressive SDR 8-bit or 10-bit planar 4:2:0, 4:2:2 or 4:4:4 AVC track with a fixed parameter set and continuous timeline. Ogg playback supports 8-bit Theora in 4:2:0, 4:2:2 and 4:4:4. Chained Ogg supports one video track per segment, with either video alone or one consistent Opus or Vorbis soundtrack in each segment. The next segment starts after the longer track. Intermediate soundtrack gaps play as silence. Picture gaps have no frames. Coded picture area is limited to 1920 × 1088 pixels. Surround Ogg Vorbis, mixed-codec Ogg chains, fragmented MP4, clean apertures, display transforms, interlaced video, 12-bit AVC, and HDR remain open.

WebM plays one selected AV1, VP8 or VP9 video track with an optional soundtrack in Opus or Vorbis with one to eight channels. Audio-only WebM supports the same audio formats. For multiple audio tracks, pass `audio_track` to `epub_embedded_audio`. The zero-based index follows audio declaration order, including unsupported codecs. With automatic source selection, this option searches WebM candidates in their authored order. It preserves the WebM display ratio and crop and streams 8-, 10- or 12-bit SDR planar YUV as RGB8. It honors laced audio and final discard padding and applies Opus pre-skip. WebM clips use the original presentation timestamps. Vorbis playback accepts consistent legacy end stamps, fills authored gaps with silence and preserves the earlier samples across an overlap. Backward block timestamps return an explicit error. AV1 playback supports a stable sequence, one operating point, and at most one displayed picture per temporal unit. Layered, monochrome and RGB AV1, HDR, RGB-coded VP9, dynamic resizing, alpha, simultaneous video playback and in-container subtitles remain open. Packaged XHTML WebVTT and TTML tracks can be synchronized with WebM pictures. [WebM container guidelines](https://www.webmproject.org/docs/container/), [Matroska AV1 codec mapping](https://www.matroska.org/technical/codec_specs.html#v-av1)

`Document.epub_embedded_text(page, media_index, track_index=None, start_us=0, end_us=None)` returns `EpubTextCue` values from a local WebVTT or TTML track. The default track takes precedence, followed by the first declared track. Supply the zero-based track index to override it. Cues have half-open bounds in microseconds on the original media timeline. Open-ended TTML cues have no end unless clipped. WebVTT cues retain authored settings, region IDs and cue markup alongside plain text. TTML supports media-time clock, offset, frame, subframe and tick expressions, nested parallel and sequential timing, timed spans, line breaks and `xml:space`. The caller renders the text. Subtitle drawing, timed TTML regions and segmented WebVTT timestamp maps remain open. Each local track is limited to 2 MiB and 10,000 projected cues. [WebVTT](https://www.w3.org/TR/webvtt1/), [TTML timing](https://www.w3.org/TR/ttml2/#timing)

Each cue's `runs` tuple contains owned `EpubTextRun` values in text order. Concatenating their text gives the existing plain-text projection. Each run has an `EpubTextStyle` with typed font style, bold and decoration flags, optional RGBA8 colors, CSS class names, voice, and language. WebVTT exposes inline bold, italics, underline, default foreground and background color classes, voice and language annotations, and in-cue timestamps in `timestamp_us`. Timestamps retain the original source clock after a seek. WebVTT cue markup continues to carry ruby annotations and other authored cue syntax.

WebVTT `STYLE` blocks before the first cue can set color, color-only backgrounds, font weight and style, and decoration lines. The parser supports plain `::cue` and compound `::cue(...)` selectors for the root, cue IDs, inline tags and classes, voice and language attributes, and `:lang()`. Language selectors use the track's `srclang` and nested WebVTT language annotations. Declarations use `!important`, specificity and source order. The cue background is `EpubTextCue.background_color`. Inline background colors stay with the runs. Stylesheets have a combined 64 KiB limit, with additional limits on rule size, selector counts, and matching work. Resource references and at-rules return explicit unsupported errors. Regions, dynamic `:past` and `:future` selectors, combinators, and CSS layout and effects remain open. [WebVTT cue styling](https://www.w3.org/TR/webvtt1/#the-cue-pseudo-element)

TTML exposes foreground color, weight, font style, underline, line-through, overline, and language. Local style references resolve in declaration order with inline declarations taking precedence. Language and supported typography inherit through content elements. Consecutive TTML intervals with identical words and different styles stay distinct. A cue's legacy equality and hash still compare its original fields. Compare `runs` and `background_color` for style equality. The synchronized video iterator returns the same typed cues. It leaves caption drawing to the caller. TTML region styling and layout remain open. [TTML styling](https://www.w3.org/TR/ttml2/#styling)

TTML supports one-shot inline `<set>` changes for foreground color, font weight and style, and text decoration. Place the set inside parallel body, division, paragraph, or span content. Its begin, end and duration use the enclosing element's media-time clock. The style reverts when the set ends and respects the target's time bounds. Different properties can change together. Cue intervals split when the effective style changes, including during synchronized video playback, and adjacent equal styled intervals merge. Repeats, frozen fills, region animation, out-of-line animation, continuous animation, and overlapping sets on the same property of one target return explicit unsupported errors. [TTML animation](https://www.w3.org/TR/ttml2/#animation)

Local video URLs can select a spatial rectangle with `#xywh=10,20,80,60`, `#xywh=pixel:10,20,80,60`, or `#xywh=percent:25,25,50,50`. Combine one spatial and one temporal range with `&amp;` in XHTML, in either order. `EpubMediaSource.fragment_xywh` exposes the authored `(unit, x, y, width, height)` tuple or `None`. Pixel units use the displayed picture after applying the container crop and pixel aspect ratio. The returned RGB raster covers the rectangle and retains the original pixel aspect ratio. Integer percentages round the top-left down and the size up and must fit within 100 percent. A pixel rectangle extending beyond a picture edge is clipped at that edge. An origin outside the picture, an invalid rectangle or repeated dimensions return explicit errors. The spatial selection preserves soundtrack and caption timing. [Media Fragments URI spatial dimension](https://www.w3.org/TR/media-frags/#naming-space)

Local WebM and Ogg URLs can select named tracks. For example, `#track=Wide%20Angle&amp;track=Commentary&amp;t=0.5,2.25` selects one picture track and one soundtrack in XHTML. Repeat `track` for each name and use percent encoding for spaces and separators. Name matching is exact and case sensitive. WebM uses the TrackEntry Name and Ogg uses the Skeleton Name associated with each stream serial. `EpubMediaSource.fragment_tracks` exposes the distinct decoded names in authored order. A named fragment selects at most one video and one audio track. Calls for a media type omitted from the fragment return an explicit unsupported error. Absent and ambiguous names fail explicitly, and an ordinal selector cannot be combined with named selection. Local caption files remain selected by `text_track`. [W3C track fragment syntax](https://www.w3.org/2008/WebVideo/Fragments/WD-media-fragments-spec/), [Matroska track names](https://www.rfc-editor.org/rfc/rfc9559.html#section-5.1.4.1.18), [Ogg Skeleton Name](https://wiki.xiph.org/SkeletonHeaders#Name)

In a chained Ogg resource, each segment must declare the selected names with consistent media types and codecs. Named Ogg supports Skeleton 3.0 and 4.0 with zero time origins and zero selected track base granules. When both video and audio are selected, the end of the longer selected track determines the next segment's start. Crop selection, seeking, and captions use that presentation clock. [Ogg Skeleton](https://xiph.org/ogg/doc/skeleton.html)

A local WebM source can resolve an ID such as `#id=chapter-2` to a temporal fragment. Match an exact Matroska ChapterStringUID or a decimal ChapterUID. `EpubMediaSource.fragment_id` exposes the decoded ID. The interval starts at the chapter's authored time and ends at its explicit end, the next later sibling marker, the enclosing chapter boundary, or the end of the source. The reader rounds nanosecond bounds up to its microsecond clock and intersects the chapter with the requested interval. Named tracks and a spatial crop can be combined with an ID. The same interval bounds audio, video, and synchronized captions.

Duplicate or missing IDs, a URL combining `id` with `t`, and malformed chapter timings return explicit errors. This profile supports simple local chapters, including nested chapters. An ID that refers to ordered, linked, restricted, or command-bearing chapters returns an unsupported error. Chapters stored after media clusters require a valid SeekHead. Remote sources remain inert. ID fragments for other media containers remain open. [W3C ID fragment syntax](https://www.w3.org/2008/WebVideo/Fragments/WD-media-fragments-spec/), [Matroska Chapters](https://www.rfc-editor.org/rfc/rfc9559.html#section-20)

Pass `text_track` to `epub_embedded_video` to attach the selected track to each frame's `text_cues`. A caption boundary inside a decoded frame divides its presentation interval while reusing the same RGB bytes. Clips reconstruct overlapping active cues at the seek point. A video interval can carry up to 128 simultaneous cues. [Media Fragments URI](https://www.w3.org/TR/media-frags/#npttimedef)

EPUB 3 media overlays are exposed under `Document.metadata["media_overlays"]`, keyed by manifest ID. They retain nested SMIL sequences, structural roles, target element IDs, and local audio paths. `Document.epub_media_cues(page)` gives a chapter's ordered cues with audio bounds in integer microseconds. An absent clip end means the end of the source audio. `Document.epub_narration(page)` decodes local MPEG Layer III, AAC-LC in MP4, Ogg Opus in mapping families 0 and 1, Ogg and WebM Vorbis with one to eight channels, and PCM WAVE to signed 16-bit PCM WAVE and extracts readable text for text-only cues. `Document.play_epub_narration(page, ...)` sequences the caller's blocking audio, speech and active-target callbacks. Both methods accept `start_cue`, a zero-based chapter cue index applied before `skip_roles`. Pass `audio_tracks={"EPUB/audio/voices.webm": 1}` to select the second WebM audio track for that resource. The `opus_tracks` mapping remains available for Ogg Opus. Select each resource through one mapping.

Both audio endpoints round up to the next sample timestamp when needed and exclude the end sample. Source audio is bounded to 32 MiB and each buffered clip to 16 MiB of PCM. Pass `chunk_frames` from 1 to 262,144 to process a long cue in smaller WAVE clips. `epub_narration` yields the same target information for each of its audio chunks, and `play_epub_narration` holds the active target across those chunks.

MP4 playback honors a continuous presentation edit. MP3 applies encoder delay and end padding on validated Xing/Info tags from LAME or FFmpeg, and files without recognized timing metadata use the MPEG frame timeline. Ogg Opus accepts single and sequentially chained mono, stereo and surround streams. Each link applies its own pre-skip and output gain and ends at its final granule. Cues use one continuous timeline. Surround output uses extensible WAVE with each speaker identified by the channel mask. A chain uses the combined speaker positions of its non-mono links, leaving absent speakers silent. Mono uses the center speaker when the output has one and otherwise plays through both front channels. Multiplexed `audio/ogg`, `application/ogg` and `video/ogg` resources can supply narration. Both narration methods accept `opus_tracks`, a mapping from decoded archive paths to zero-based Opus track indices in identification page order. For example, `opus_tracks={"EPUB/audio/voices.ogg": 1}` selects the second Opus track in every segment of that resource. A missing selection for concurrent tracks or an index absent from a segment returns an explicit error. The reader validates Ogg transport for every stream, including unselected tracks. To package Opus for an authored overlay, use the EPUB core type `audio/ogg; codecs=opus` and provide an explicit clip end. Fragmented MP4, built-in speech synthesis, and an audio-device implementation remain open. [EPUB 3.3 media overlay specification](https://www.w3.org/TR/epub-33/#sec-media-overlays), [Ogg Opus specification](https://www.rfc-editor.org/rfc/rfc7845.html)

Ogg and WebM Vorbis use the standard encoded channel order for one to eight channels. Surround output uses extensible WAVE with its speaker mask and samples in WAVE order. Applications define the speaker order for Vorbis streams with more than eight channels. Playback of those layouts returns an explicit error. Ogg Vorbis uses granule positions for leading silence or overlap trim and to trim the presentation tail. Chained Vorbis audio preserves a single sample rate and channel count. Both Ogg audio codecs validate the surrounding multiplexed transport. Automatic selection prefers Opus when both codecs are present. [Vorbis I specification](https://xiph.org/vorbis/doc/Vorbis_I_spec.html)

Pass ordered `EpubOverlayCue` and `EpubOverlaySequence` values to `edit_epub_structure(overlays=...)` to attach authored narration to a chapter. A sequence can contain cues and other sequences, target a fragment or the whole chapter, and set `epub_type` roles inherited by its cues. The editor accepts up to 32 levels of sequence nesting and 10,000 timing entries per edit. Supply `None` to detach a chapter's association. Replacing or detaching a chapter in a shared SMIL resource preserves the other chapters' cues, IDs and roles. The editor removes empty sequences, retargets surviving containers when needed, and updates the SMIL and publication duration metadata. Open-ended clips can use the presentation duration of supported local audio, including audio replaced by the same edit. [EPUB 3.3 overlay structure](https://www.w3.org/TR/epub-33/#sec-media-overlays-structure)

The reader parses bounded UTF-8 XML and recognizes plain HTML and selected legacy XHTML, NCX and SVG doctype declarations. Parsing is offline. Custom DTDs and script execution are unsupported. Supported XHTML and static SVG CSS declarations can use unregistered custom properties and var() fallbacks. Custom properties inherit their computed values and keep case-sensitive names. Substitution handles cycles and preserves shorthand cascade order. [CSS custom properties](https://www.w3.org/TR/css-variables-1/) Broader CSS coverage, registered custom properties, complex SVG text fallback, and DRM remain outside the supported preview profile. Static SVG supports `use` with literal fragment IDs for graphics and symbols in the same SVG subtree. Both `href` and `xlink:href` are accepted, with `href` taking precedence. Each SVG use instance inherits computed custom properties from its host, including through nested references and symbols. Supported stylesheet and inline declarations substitute these properties in the instance's scope. They retain local overrides, fallbacks and cycle handling. Reused text inherits the supported font family, weight, width, style, optical sizing and variation settings from each instance. Local paint servers inside a reused subtree keep the instance's colors. Use stylesheet or inline CSS declarations for variable substitution. Reopened fixed-layout PDF preserves measured SVG text links and links around rendered instances. Links inside reused SVG graphics follow the rendered instances and their clipping. Fragment links prefer a directly drawn target. If the target appears only through reuse, they use its first visible instance in paint order. Geometry that cannot be matched to the original native drawing returns an explicit export error. Missing and duplicate targets, cycles, and expansions exceeding the node, byte or depth limits return explicit errors. SVG scripts, external and data URLs, and referenced SVG images inside SVG are outside the supported profile. [SVG use elements](https://www.w3.org/TR/SVG2/struct.html#UseElement) See the [EPUB specification](../.kiro/specs/epub-support/requirements.md) for details.

ZIP safety preflight for DOCX, PPTX and EPUB bounds raw central-directory entries and rejects duplicate names and malformed directories before constructing archive indexes. ZIP64, multi-disk archives, ZIPs with trailing data, and archives with ambiguous end records are explicitly unsupported. EPUB additionally rejects multiple package rootfiles, inconsistent local/central headers and end-record signatures in the ZIP comment. ZIP data descriptors remain supported.
